# Vue 3 前端技术栈规范

## 启用条件

仅当 [项目配置](../项目配置.md) 明确启用本 profile，且目标项目实际采用 Vue 3、TypeScript、Vite 与 Element Plus 时生效；未启用、技术栈不符或尚未核实，均不适用。先执行[通用前端开发约束规范](../docs/AI-前端开发约束规范.md)；本文件只补充对应技术栈的实施要求，不改变现有架构、主题、错误政策或授权边界。项目配置与已有实现冲突时先核实，实质冲突按通用规范澄清。

## 配置与类型

- 从目标项目实际清单和锁文件确认依赖、版本、运行方式、脚本及目录；不得编造路径、版本、组件或检查命令。仅运行已配置且本次获准的检查。
- 沿用已有 TypeScript `strict` 设置，不放宽配置以规避错误；新增代码禁止 `any`、无依据的非空断言、双重断言和 `@ts-ignore`。外部未知数据用 `unknown` 经验证或收窄后再使用；组件输入输出、请求响应及状态使用明确类型，并与后端的空值、缺省、枚举、单位契约一致。
- 局部交互状态归组件或组合式函数；跨页面状态沿用目标项目已经采用的机制。不自行安装或接入 Axios、Pinia、VueUse 或其他框架、请求和状态库。

## Vue 组件与副作用

- 新增 Vue 3 组件采用 Composition API 与 `<script setup lang="ts">`，但既有模块保持已采用的组织风格；不得为统一写法重写既有组件。
- 页面组织流程，组件负责独立展示或交互，复用目标项目现有组件、布局、请求客户端、API 方法、状态类型和样式；修改共用组件前检查全部调用方和默认行为。
- `computed` 只计算派生值；不得在 `computed` 或模板表达式中隐蔽执行请求、写入状态或产生其他业务副作用。`watch` 仅响应明确的数据变化，避免重复请求和循环更新。
- 订阅、计时器、事件监听、轮询及未完成请求应明确取消、卸载清理或结果失效边界；在工作区隐藏、参数切换及请求竞态时只处理有效结果。不要仅因组件挂载而启动无需求依据的后台任务。

## 请求与验证

- 页面及业务组件使用目标项目已存在的 API 层与统一请求客户端；不在组件中另建 `fetch` 或 `axios` 调用链。若目标项目的分层不同，沿用其已批准的契约，不凭此 profile 发明目录或请求封装。
- 请求失败应终止当前操作、恢复对应 loading/保存状态；错误展示和失败兜底必须遵守目标项目已批准的政策，不将失败伪装为空数据或成功，也不自行追加降级路径。
- 根据目标项目实际配置执行适用的类型检查、构建与本地验证；未配置或未执行的检查如实记录。本文件不附带或安装任何外部技能。
