# FastAPI 技术栈规范

## 启用条件

仅当 [项目配置](../项目配置.md) 明确启用本 profile，且目标项目实际采用 FastAPI 时生效；未启用或技术栈不符时不适用。先执行[通用后端开发约束规范](../docs/AI-后端开发约束规范.md)、[接口与安全规范](../docs/AI-接口与安全规范.md)；本文件不授权变更目标项目架构、数据库、运行方式或错误契约。

## 路由、装配与模型

- 从目标项目实际入口核实路由、`APIRouter` 注册、应用装配和 lifespan 的现有组织方式。路由负责 HTTP 输入输出，业务规则沿用既有服务边界；不假定有 `create_app` 或固定目录。应用级资源在已批准的入口/lifespan 或既有机制中初始化和释放。
- 用 Pydantic 模型或目标项目批准的明确结构校验输入，明确字段类型、必填、可空和缺省语义；JSON 输出以响应模型、`response_model` 或字段白名单限制实际响应。不得直接暴露数据库实体、内部异常、秘密或无消费用途的字段。
- `Response`、错误响应、SSE 和下载不应因为绕过 `response_model` 而逃避输出边界；保持真实 HTTP 状态码、已批准的异常形态和调用方契约。调整接口时同步核对前端类型及其他消费者。
- 使用现有 `Depends` 或其他已批准的依赖机制管理配置、客户端及数据库会话；明确会话作用域、事务提交/回滚和清理边界。不要在模块导入时写数据库、联网或执行外部副作用。

## 并发、存储与资源

- 按实际调用链选择 `def` 和 `async def`：阻塞 I/O 不应在事件循环里直接执行；同步函数的线程池运行方式、同步依赖、异步客户端和执行器边界以目标项目真实配置核实。不得假定给函数加 `async` 就使同步数据库或网络调用非阻塞。
- 持久化写入明确事务、失败回滚、唯一性和并发不变量；结构变更先核实目标项目数据库和迁移方案，评估旧数据、部署顺序、重复执行及恢复。不可逆迁移按项目授权执行，不能因为本 profile 自动接入启动迁移。
- 外部调用定义连接/读取或整体超时、资源和输出上限、异常分类与取消后的释放。流式响应、后台任务和应用关闭时检查断连、取消、生成器关闭、会话/客户端释放及已开始副作用的结果状态，不把中断当成功。
- 若项目使用 SSE，先确认事件类型、数据字段、心跳/结束、失败、取消与客户端解析契约；下载核对媒体类型、文件名、编码/转义、路径边界和失败响应。改变生产方必须联动消费方验证。

## 明确边界与验证

- 数据库、迁移、应用工厂、进程数、任务执行器、认证和包管理方式均由目标项目核实。只沿用已批准、实际存在的方案，不因通用示例接入替代库或工具。
- 按实际检查配置验证正常、错误、权限、字段过滤、事务、并发、超时、取消以及流/下载的受影响场景；未配置或未执行项如实说明。不安装依赖或外部技能。
