# UI 规范样板（可填写与扩展模板）

本文件用于锁定目标项目的视觉风格、组件外观和交互状态，限制 AI 在开发中自行重新设计 UI。正文为待填写模板。模板不要求实现所有列出的组件，不预设框架、设备、主题或组件库。

## 一、填写与启用规则

1. 在[项目配置](../项目配置.md)登记本规范的启用范围和批准依据；本文件记录该范围内 UI 的具体约束，项目配置通过引用指向本文件，避免重复维护数值。文件存在或字段填满均不代表已经启用。
2. 将 `【待填写：…】` 替换为经确认的值、变量或真实实现引用。数值写清单位；引用写清文件、导出项或组件变体；禁止只写“统一”“美观”“默认”。尚未核实的路径不能写成已有文件。
3. 每项状态只填写“待确认、已批准、沿用已核实实现、不适用”之一；沿用必须注明实现、版本或基准证据，不适用必须注明原因。下文表格未单列状态时，填写内容必须同时标明状态。
4. 仅补齐当前任务涉及的规则即可。当前任务依赖的未决项，先查现有已批准设计和实现；能够明确复用时记录证据后沿用，无法确定时暂停该样式决策并列出待确认项，其他已授权工作继续。禁止把空白解释为允许自由设计。
5. 已有项目先核实并合并既有规范。发生颜色、布局、设备、组件行为或错误政策冲突时按[工程治理规范](../docs/AI-工程治理与需求规范.md)处理，禁止直接覆盖。不得以锁定外观为由移除必要信息、权限语义或可访问性。
6. 外部设计示例仅作候选参考，只有明确登记采用的规则才生效；采用时将值或精确规则引用填入正文，不得将示例自动作为缺项默认值。填写全局变量和组件参数时，可以查阅[前端样式推荐表](../docs/前端样式推荐表.md)，区分官方值与综合建议，核对所选组件库版本及适用设备后登记采用依据。

## 三、AI 样式实施边界

- 必须优先复用已批准的布局、变量、组件及变体。新增页面沿用同类页面的结构和密度，禁止因“现代化”“美化”或外部技能建议擅自换色、改圆角、加阴影、重排布局、替换图标或增加动画。
- 必须依次核对适用规则：已批准且仍有效的项目例外、本文组件专属约束、本文全局变量与状态规则、已核实的既有组件基线。外部设计和第三方组件库示例不参与自动补全；来源冲突须明确解决，不能择取偏好的样式。
- 允许的页面差异仅限已批准的内容、数据、权限和布局参数。页面不得自建第二套按钮、输入框、状态色或间距体系；确需新变体时按第八节登记用途和边界。
- 颜色、字号、尺寸、间距、圆角、阴影、层级和动效必须引用经确认的变量或组件参数。必要的业务尺寸须登记；禁止散落未登记的魔法数、行内样式、任意值工具类及未经登记的全局选择器覆盖。
- 组件库通过其当前版本支持的主题入口和公共 API 映射；不得假定存在某个 API，不得未经登记深度覆盖内部 DOM、滥用 `!important` 或修改第三方源码。浮层挂载到页面外时仍须继承已批准主题。
- 样式任务不得改变数据、请求、权限或失败语义。加载、无数据、无结果、失败、部分完成和结果未知分别表达，禁止用动画、空态或假数据掩盖错误。
- 全部标题、字段、提示、状态和操作必须服务用户任务；只因接口有字段而展示内部对象、调试信息或无用途统计不被允许。低频有效明细可按需展开，核心结果和危险影响保持可见。

## 六、组件约束填写清单

每行是一个可独立扩展的组件入口。填写“已批准约束 / 实现引用”时，逐项回答该行参数，可引用第四、五节的明确变量，禁止只填“参考全局”。状态为“已批准”或“沿用已核实实现”的组件必须具备完整约束；内容较多时使用第八节卡片，以组件编号关联。全部初始状态为待确认，不表示要开发全部组件。

本清单按跨组件库的用途归类，不保证某个库或版本内置全部能力。必须核实实际组件来源、版本、扩展包及适用许可；列出组件不构成安装依赖、自行开发或启用新设备范围的授权。同一实现承担多个条目时分别记录用途并引用同一入口，禁止为匹配清单重复封装。第 6.5～6.10 节为补充条目，尤其媒体、移动端、业务及 AI 组件仅按已确认需求填写，不要求逐项实现或为无关条目编造配置。
