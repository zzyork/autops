# autops UI 规范（紧凑桌面控制台）

本文件是本项目已选 UI 规则、尺寸与交互政策的唯一权威登记；[项目配置](../项目配置.md)只登记启用范围与验证，[前端样式推荐表](../docs/前端样式推荐表.md)仅作候选参考。2026-10-20 用户授权按其紧凑方案改造现有桌面页面。下文仅填实际采用的组件；未填写条目保持待确认，不构成启用或新功能要求。数值为 CSS px（字体代码以 rem 实现），实际变量与局部业务布局以引用的源码为准。

## 一、填写与启用规则

1. 在[项目配置](../项目配置.md)登记本规范的启用范围和批准依据；本文件记录该范围内 UI 的具体约束，项目配置通过引用指向本文件，避免重复维护数值。文件存在或字段填满均不代表已经启用。
2. 将 `【待填写：…】` 替换为经确认的值、变量或真实实现引用。数值写清单位；引用写清文件、导出项或组件变体；禁止只写“统一”“美观”“默认”。尚未核实的路径不能写成已有文件。
3. 每项状态只填写“待确认、已批准、沿用已核实实现、不适用”之一；沿用必须注明实现、版本或基准证据，不适用必须注明原因。下文表格未单列状态时，填写内容必须同时标明状态。
4. 仅补齐当前任务涉及的规则即可。当前任务依赖的未决项，先查现有已批准设计和实现；能够明确复用时记录证据后沿用，无法确定时暂停该样式决策并列出待确认项，其他已授权工作继续。禁止把空白解释为允许自由设计。
5. 已有项目先核实并合并既有规范。发生颜色、布局、设备、组件行为或错误政策冲突时按[工程治理规范](../docs/AI-工程治理与需求规范.md)处理，禁止直接覆盖。不得以锁定外观为由移除必要信息、权限语义或可访问性。
6. 外部设计示例仅作候选参考，只有明确登记采用的规则才生效；采用时将值或精确规则引用填入正文，不得将示例自动作为缺项默认值。填写全局变量和组件参数时，可以查阅[前端样式推荐表](../docs/前端样式推荐表.md)，区分官方值与综合建议，核对所选组件库版本及适用设备后登记采用依据。

## 三、AI 样式实施边界

- 必须优先复用已批准的布局、变量、组件及变体。新增页面沿用同类页面的结构和密度，禁止因“现代化”“美化”或外部技能建议擅自换色、改圆角、加阴影、重排布局、替换图标或增加动画。
- 必须依次核对适用规则：已批准且仍有效的项目例外、本文组件专属约束、本文全局变量与状态规则、已核实的既有组件基线。外部设计和第三方组件库示例不参与自动补全；来源冲突须明确解决，不能择取偏好的样式。
- 允许的页面差异仅限已批准的内容、数据、权限和布局参数。页面不得自建第二套按钮、输入框、状态色或间距体系；确需新变体时按第八节登记用途和边界。
- 颜色、字号、尺寸、间距、圆角、阴影、层级和动效必须引用经确认的变量或组件参数。必要的业务尺寸须登记；禁止散落未登记的魔法数、行内样式、任意值工具类及未经登记的全局选择器覆盖。
- 组件库通过其当前版本支持的主题入口和公共 API 映射；不得假定存在某个 API，不得未经登记深度覆盖内部 DOM、滥用 `!important` 或修改第三方源码。浮层挂载到页面外时仍须继承已批准主题。
- 样式任务不得改变数据、请求、权限或失败语义。加载、无数据、无结果、失败、部分完成和结果未知分别表达，禁止用动画、空态或假数据掩盖错误。
- 全部标题、字段、提示、状态和操作必须服务用户任务；只因接口有字段而展示内部对象、调试信息或无用途统计不被允许。低频有效明细可按需展开，核心结果和危险影响保持可见。

### 5.1 执行状态与颜色规范

已批准：2026-10-21 用户明确要求补充“未开始、进行中、已完成、未完成、已中止”的文字/图标颜色、背景颜色和变量命名规范。本节适用于任务、检查、测试、报告生成等执行状态的标签、图标和状态提示；风险等级、字段校验、请求错误及停止操作按钮仍执行各自规则。后续新增或修改执行状态展示时必须遵守本节。

下表中的展示键仅用于 UI 颜色角色命名，禁止据此新增或改写接口枚举、持久化状态或后端执行逻辑。具体文案可以沿用业务契约中的“排队中”“执行失败”“部分完成”等名称，但必须根据明确状态映射颜色，禁止匹配提示文字决定状态。

| 状态 / 展示键 | 使用条件与语义边界 |
| --- | --- |
| 未开始 / `not-started` | 尚未开始执行，包括已确认处于排队等待的任务；尚未执行不等于执行失败 |
| 进行中 / `in-progress` | 执行方明确仍在处理；已提交停止请求但尚未确认执行结束时，保留原有的“未开始”或“进行中”类别，并显示“正在中止”等真实进度；禁止将排队任务仅因提交停止请求改为进行中 |
| 已完成 / `completed` | 执行方确认按业务契约完整成功结束；不能仅凭进度达到 100%、请求返回、连接关闭或存在部分结果判为完成；执行完成与风险正常分别表达 |
| 未完成 / `incomplete` | 执行已结束且未被明确确认为已中止，但失败、部分完成或结果缺失导致未满足完整完成条件；尚在等待或执行的任务不能只因未结束归入此类；已有部分结果必须保留 |
| 已中止 / `aborted` | 执行方明确确认已取消或中止本次执行；点击停止、取消浏览器请求、超时或断连不能单独作为已中止证据，也不能据此声称远程操作已回滚 |

| 状态 | 文字 / 图标色及基础变量 | 背景色及基础变量 | 前景变量 | 背景变量 |
| --- | --- | --- | --- | --- |
| 未开始 | 灰色 #596371，`--ui-text-secondary` | #ECEFF3，`--ui-surface-muted` | `--ui-status-not-started-fg` | `--ui-status-not-started-bg` |
| 进行中 | 蓝色 #315F89，`--ui-info` | #EAF1F7，`--ui-info-soft` | `--ui-status-in-progress-fg` | `--ui-status-in-progress-bg` |
| 已完成 | 绿色 #287348，`--ui-success` | #EAF4ED，`--ui-success-soft` | `--ui-status-completed-fg` | `--ui-status-completed-bg` |
| 未完成 | 红色 #B13737，`--ui-danger` | #FAECEC，`--ui-danger-soft` | `--ui-status-incomplete-fg` | `--ui-status-incomplete-bg` |
| 已中止 | 黄褐色 #8A5C10，`--ui-warning` | #FBF3DF，`--ui-warning-soft` | `--ui-status-aborted-fg` | `--ui-status-aborted-bg` |

变量命名与使用必须遵守以下规则：

- 格式固定为 `--ui-status-{state}-fg` 与 `--ui-status-{state}-bg`；`state` 只能使用上表五个展示键，使用小写英文与连字符，`fg` 表示文字和图标前景，`bg` 表示状态容器浅色背景。禁止用中文、业务页面名或 `red`、`green` 等色名替代状态名。
- 实施时必须在 `frontend/src/styles/main.css` 的 `:root` 中集中定义上述别名，值使用 `var(...)` 引用上表基础变量；业务样式必须引用状态别名，禁止重复硬编码色值或在页面定义同名变量。仅为边框需要时直接复用该状态的 `fg`，不另建同值边框变量。
- 同一状态的文字和图标必须使用相同前景色，SVG 通过 `currentColor` 继承。带底色的状态标签或提示使用对应 `bg`；纯文字或独立图标可以透明背景，禁止为着色而覆盖整张业务卡片或整行表格。红色“未完成”状态提示必须使用状态前景色，不能只使用辅助灰字。
- 状态必须同时有明确文字、可访问名称或可区分图形，禁止只靠颜色表达；关键的未完成或已中止影响必须保持可见。风险结论与执行状态分别显示，例如“已完成”可以同时存在“严重”风险，禁止用完成状态的绿色覆盖风险红色。
- 部分完成按“未完成”的红色表达，仍保留“部分完成”文案和真实结果；已跳过、不适用、身份待确认和结果未知按各自业务契约单独表达，禁止仅凭名称强行归入这五类。已有 `interrupted` 等状态必须核实契约：明确确认中止时才映射“已中止”，不能完整完成且有结束证据时映射“未完成”，无法确认结果时保留未知或中断语义。
- 必须核对实际背景上的对比度：普通文字至少 4.5:1，必要的状态图标、控件边界和焦点至少 3:1；透明背景、叠加和禁用态仍须按实际背景审核。上表纯色前景/背景对的计算值依次约为 5.28:1、5.89:1、5.13:1、5.26:1、5.25:1，仅证明表内色对，不代表页面已完成视觉或可访问性验证。

实施状态：2026-10-21 已按用户要求接入十个状态别名。`types/executionStatus.ts` 约束五类展示键；`ui.css` 的 `.ui-execution-status` 通过 `data-execution-state` 映射前景与浅底，局部 `--ui-execution-fg` 和 `--ui-execution-bg` 只转发所选别名。`ElTag` 通过其已有 `--el-tag-text-color`、`--el-tag-bg-color`、`--el-tag-border-color` 接口使用这些变量；`.ui-execution-notice` 的上下/左右内边距分别为 `--ui-space-1`/`--ui-space-2`，圆角为 `--ui-control-radius`，字号/行高为 small。纯文字、图标和统计只设置前景，不覆盖整张卡片或表格行。

巡检任务、检查、记录概览、AI 报告及对话任务卡已使用上述映射；部分完成和已结束失败提示使用红色，未完成汇总从检查实际状态派生，有终态失败时为红色，仅有等待/运行时分别为灰/蓝色。当前检查契约的 `skipped` 是流程终结后未执行的检查，因此保留已跳过文案并按不完整结果着色；风险“不适用”和“无法判定”继续独立表达。

`TestStatus.vue` 保留既有图标、tooltip、可访问名称和焦点入口，新增可选 `label` 供 SSH 弹窗统一显示同色图文和浅底；无标签时保留图标热区。测试的 `queued` 表示尚未提交，使用横线图形和未开始色；`pending` 表示本地请求处理中，不能据此声称远端已开始执行。未测试、通过和失败分别使用对应执行状态色，身份待确认和结果未知不归并。

巡检、报告和聊天的历史中断缺少原因区分，SSH 中断也可能来自资产变更，均保留原有中断文案，不宣称用户已中止；已结束不完整结果使用红色。批量 SSH 的警告色仅表示本地后续提交已停止，正在执行的主机仍可能返回结果。聊天消息的 `failed` 可能是执行中占位，仅在会话活动确认结束后显示失败终态，否则提示发送状态待确认；等待停止确认继续显示处理进度，停止操作按钮保持原危险色。

`ChatMessageItem.vue` 沿用 UI-89 的消息外观，接收 `message` 和 `resultConfirmed`，只展示角色、内容及结果提示，无请求或事件副作用。`ChatView.vue` 在发送/决策开始和收尾、停止、切换会话时清除旧确认；只有本轮操作结束后发起且代次仍有效的活动查询返回空闲时才确认消息结果，查询失败继续待确认。
