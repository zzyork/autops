# autops 变更审核

默认只读审核。用户已授权修复时，可以在原授权范围内修改并重新验证；单纯要求审核不授权提交、推送、迁移或运行真实运维操作。

通过 `/autops-review` 的专用只读 Agent 调用时，始终保持只读，不切换到修复流程；需要修改或执行 Shell 验证时，在报告中列出待处理项，由用户在正常开发会话授权执行。每项任务只进入本审核流程一次，读取开发技能只获取检查依据，不重新进入实施或末尾审核流程。

## 审核过程

1. 完整阅读根目录 `AGENTS.md`、三份开发规范、相关计划和源码。工具权限允许时检查 `git status --short`、目标差异及必要的上下文；专用只读入口仅核对用户提供的差异或明确指定的源码，不能自动取得工作区差异。区分本次修改和原有未提交工作，不撤销他人修改。
2. 前端加载 `autops-frontend`、`vue`，后端加载 `autops-backend`、`fastapi`，跨端加载两组；已在本轮完整读取且未变化的内容不重复加载。
3. 从实际入口追踪输入、状态、权限、存储、输出和调用方，检查以下适用项目，而非仅按关键词扫描：
   - 正确性：业务不变量、事务、并发、取消、重复执行和资源释放。
   - 契约：请求模型、实际 JSON、错误、SSE、下载、前端类型及旧消费者。
   - 安全：对象与字段权限、输入校验、命令注入、路径穿越、XSS、凭据和日志泄露；优先核对修改涉及的边界。
   - 失败路径：默认值或静默异常是否掩盖失败，未知结果是否被当成功，失败后是否继续执行依赖步骤。
   - 前端：请求封装、状态归属、共用组件、桌面布局、最小必要信息与可访问性。
   - 简约性：新增抽象、依赖、状态或任务是否有明确用途，是否误删必要保障或扩大修改范围。
4. 对候选问题查上下文、调用方和反例，排除仅由个人风格偏好产生的发现。优先报告能说明触发条件与后果的问题，无法确认的内容标为待验证。
5. 执行与改动风险相符且已经存在的检查。修复后验证原问题及受影响路径；安全或兼容问题必要时补充可复现用例，避免只重复实现的测试。

## 输出

- 按严重程度列出问题，包含文件位置、触发条件、影响与具体修改建议。
- 未发现问题时明确限定为本次检查范围，列出已执行检查、未执行项和残余不确定性。
- 不把上游技能存在、静态结构检查或模型自评等同于应用正确性、客户端成功加载或人工审核通过。

本技能由项目编写。审核步骤借鉴变更审核与修复后验证思路；外部来源及采纳范围见仓库根目录的 `docs/AI-编程接入指南.md`，未安装额外安全插件或扫描服务。
