# 主机管理

主机管理用于维护运维资产及其 SSH 连接信息。2026-10-21 用户要求调整表单分区并新增局域网 IP，随后明确确认：已有主机的局域网 IP 复制当前主机名称，保留原名称，之后独立编辑；主机名改为选填。

## 表单与字段

新增和编辑使用同一表单，依次展示：

| 分区 | 字段与规则 |
| --- | --- |
| 连接信息 | 地址必填，仅接受 IPv4 或 IPv6；用户名及认证所需凭据沿用现有必填规则；端口范围为 1–65535，默认 22；选择密码或 SSH 密钥认证，可关联已有跳板机 |
| 基本信息 | 主机名选填，最长 100 字符；局域网 IP 选填，最长 253 字符；分组必填；虚拟 IP 选填，沿用现有地址校验 |
| 备注 | 选填，最长 2000 字符 |

连接信息中，地址、用户名和端口同排；认证方式单独一行，密码或 SSH 密钥与跳板机并排，基本信息沿用双列。具体宽度与间距统一见 [UI 规范的 UI-02 栅格条目](../profiles/UI规范样板.md#61-框架基础与公共样式)。SSH 密钥的选中值和下拉选项仅显示密钥名称，表单内不提供管理链接。

`name` 保存用户填写的名称，允许空字符串；主机列表、连接测试、主机选择及后端生成的身份确认、密钥引用、AI 主机摘要和巡检快照在名称为空时使用连接地址识别对象。该显示值不写回资产名称。

`lan_ip` 是独立的可空文本字段，空表单值提交为 `null`。由于用户要求复制旧名称，而旧名称允许任意文本，本字段保留历史文本，不执行严格 IP 格式校验。修改它不改变 SSH 连接地址，也不直接重置连接测试结果。

## 接口与兼容

接口沿用 `/api/v1/hosts` 的查询、新建、详情、更新和删除。新建请求允许省略 `name` 和 `lan_ip`，分别使用空字符串和 `null`；更新请求仍携带 `version`，省略 `lan_ip` 时保留已有值，显式传 `null` 时清空。响应中的 `name` 返回原始名称，`lan_ip` 返回保存值或 `null`。

分组、跳板机和 SSH 密钥引用继续由后端核查；密码不回显，连接参数变更沿用重新填写密码规则；更新沿用现有事务与版本冲突保护。请求失败后结束保存状态并保留表单，统一反馈由现有入口处理。

## 自动获取基础信息

2026-10-21 用户要求在主机管理的“更多操作”增加服务器基础信息采集，并明确选择“预览后保存”：通过 SSH 读取主机名和网卡 IP，多地址时选择局域网 IP，点击保存后覆盖这两项。分组、虚拟 IP、连接信息和备注保留。本功能面向已配置 SSH 连接的单台 Linux 主机，服务器需有 `bash`、`hostname` 和 `ip` 命令，执行环境沿用 [SSH 工具库](SSH命令执行.md)；不采集系统、CPU、内存等额外资产字段。

每台主机行的“更多操作 → 获取基础信息”打开独立弹窗并发起采集，复用现有 SSH 服务器身份确认、目标及跳板机连接和凭据解析。弹窗展示当前名称、采集名称、当前局域网 IP 和带网卡名称的候选地址。唯一不同 IP 自动选中；多个 IP 由用户明确选择。候选包括 IPv4 和 IPv6，排除回环、链路本地、未指定和组播地址，不按公网/私网或默认路由猜测局域网 IP。无可选地址时显示真实空结果并禁用保存，不清除原局域网 IP。

采集接口不会更新主机字段、连接测试结果或创建巡检记录；入口中的服务器身份确认仍按原有信任规则执行，信任变更可以重置连接测试状态。保存前始终显示覆盖范围，点击“保存”才提交；新名称采用采集值，局域网 IP 保存所选地址，不带网段前缀。获取失败结束加载并显示统一请求错误；保存失败保留预览及选择，提示结果未确认，不自动重复提交。取消、超时和断连不能证明保存未发生。

| 接口 | 请求与成功响应 | 边界 |
| --- | --- | --- |
| `POST /api/v1/hosts/{host_id}/basic-info/collect` | JSON `{version}`，成功 HTTP 200：`{host_id, version, name, addresses: [{interface, address}]}` | `version` 是大于零的严格整数；主机名为 1–100 个无空白及控制字符的字符；候选地址最多 256 项，接口名最长 253 字符；响应只含预览所需字段，无凭据或命令原始输出 |
| `PATCH /api/v1/hosts/{host_id}/basic-info` | JSON `{version, name, lan_ip}`，成功 HTTP 200，返回现有 `HostResponse` | 三项必填，`lan_ip` 为单个有效 IPv4/IPv6 地址，不接受 `null`、回环、链路本地、未指定、组播或带作用域标识的地址；前端限制从采集列表选择，服务端执行字段校验，不持久化候选列表；仅更新 `name`、`lan_ip`，不经过凭据修改流程 |

两个接口沿用应用当前访问边界，未另设用户或角色权限。主机不存在返回 HTTP 404；版本冲突、重复采集或采集后连接/凭据/信任快照变化返回 HTTP 409。SSH 身份需要重新确认时沿用 `ssh_identity_required` 契约；超时返回 HTTP 504，连接、工具缺失、命令失败或无效输出返回 HTTP 502，容量不足或服务关闭返回 HTTP 503。错误不回显底层异常或远端输出，前端沿用统一“系统异常”入口；身份确认走既有业务信号。

采集为同步请求，在 FastAPI 线程池运行；每个应用进程最多同时采集 4 台，同一主机只允许一个采集。总时限 60 秒，连接沿用最多 30 秒，单命令最多 10 秒并受总截止时间限制，原始输出上限沿用 [SSH 工具库](SSH命令执行.md)。每次建立独立连接，失败停止后续步骤，最终释放通道、连接和采集名额；应用关闭时发出中断信号并等待释放。关闭弹窗、切换目标、隐藏和卸载会取消本地采集等待并使旧结果失效；后端调用仍可能在既定时限内结束，不宣称远端已中止，也不自动重试。

保存使用现有 SQLite 写事务和主机版本检查；事务失败由会话回滚。非运行中的连接测试状态保留；正在运行的测试随资产版本变化按原有主机编辑规则标记中断，防止测试使用旧快照完成。保存响应丢失后重交仍受版本检查保护，不新增补偿或后台轮询。

实现分别位于 `HostBasicInfoDialog.vue`、`api/host_basic_info.ts`、`types/hostBasicInfo.ts`、后端 `services/host_basic_info.py` 和 `schemas/host_basic_info.py`，端点沿用 `endpoints/hosts.py`。弹窗接收 `modelValue` 和 `host`，发出可见性更新及携带更新后主机的 `saved` 事件，独立管理采集、选择和保存状态，主机页面只负责入口与保存后的列表刷新。界面复用既有表单、字段标签、选择器、640 宽弹窗、状态提示及主题变量；更多操作使用 Element Plus 的点击触发菜单，选择后关闭，键盘导航和焦点沿用组件库能力，不增加主题、设备范围或依赖。

2026-10-21 核对 [Ansible Linux 网络事实采集](https://github.com/ansible/ansible/blob/devel/lib/ansible/module_utils/facts/network/linux.py)、[iproute2 地址手册](https://man7.org/linux/man-pages/man8/ip-address.8.html)、[Element Plus Dropdown 文档](https://element-plus.org/en-US/component/dropdown.html)及 [2.14.7 上游菜单样式](https://github.com/element-plus/element-plus/blob/2.14.7/packages/theme-chalk/src/dropdown.scss)。Ansible 的采集和部署范围超过两个字段的需求，本次集中复用项目巡检现有的主机名与地址采集函数和解析器；菜单沿用已有主题映射，不复制外部布局。无新增依赖、数据库字段或数据迁移。

## 巡检报告归档

巡检详情的“导出报告”按 `分组/YYYYMM/局域网IP_主机名.md` 生成 ZIP 包内的逐主机 Markdown。局域网 IP 在导出时批量读取主机管理当前保存的 `lan_ip`，历史巡检记录也使用该当前值；主机名沿用现有规则，优先使用基础信息检查采集的主机名，未采集到时使用巡检记录中的主机显示名称。局域网 IP 为空或关联主机已删除时，归档接口返回 HTTP 409，终止整包导出；前端按统一请求错误政策反馈。文件名继续清理路径分隔符、Windows 非法字符及控制字符，并检查名称长度和归档路径重名。

2026-10-21 用户明确要求巡检导出的 Markdown 使用“局域网IP_主机名.md”格式。本次复用项目已有归档和文件名校验，并核对 [Python 3.13 zipfile 文档](https://docs.python.org/3.13/library/zipfile.html#zipfile.ZipFile.writestr)及 [CPython 上游文档](https://github.com/python/cpython/blob/3.13/Doc/library/zipfile.rst)的成员路径与 UTF-8 编码说明，无新增依赖或数据迁移。

## AI 对话中的资产表格

2026-10-21 用户要求 AI 聊天支持 Markdown，并将资产表格限定为“主机名、局域网IP、连接地址”三列。`query_assets` 从现有主机记录读取 `lan_ip`，与 `name`、`address` 一起提供给模型；系统提示要求按上述顺序生成 Markdown 表格，ID、版本和分组等字段仅供工具处理，不展示在回复中。`lan_ip` 为 `null` 时表达为“未填写”，不从其他字段推导；旧工具历史未保存该字段时，系统提示要求模型重新查询。

历史消息和工具历史保持原样保存，因此旧回复可以按 Markdown 展示，其原有表格列不会被追溯改写。巡检计划的 ID、版本快照和确认执行契约继续由现有逻辑管理，本次不改变数据库结构或执行逻辑。

前端复用 `ChatMessageItem.vue` 展示历史及流式消息，助手内容通过纯展示组件 `ChatMarkdownContent.vue` 渲染，输入仅为内容字符串，无请求和业务事件副作用。用户消息继续按原始文本展示。样式和输入安全边界统一见 [UI-76 Markdown 渲染](../profiles/UI规范样板.md#68-可选媒体内容与编辑组件)。

选型前核查项目依赖，未发现现成 Markdown 渲染能力；2026-10-21 核对 [markdown-it 上游仓库](https://github.com/markdown-it/markdown-it/tree/15.0.3)、[npm 元数据](https://registry.npmjs.org/markdown-it/15.0.3)和[安全说明](https://github.com/markdown-it/markdown-it/blob/15.0.3/docs/safety.md)。采用其内置表格与转义功能，禁用 HTML 和图片解析，避免自研解析器及额外净化、高亮依赖；15.0.3 自带 TypeScript 类型，并修复了 [GHSA-gfr2-rv44-r23c](https://github.com/markdown-it/markdown-it/security/advisories/GHSA-gfr2-rv44-r23c) 所述引用定义解析复杂度问题。仅在前端新增此 MIT 许可依赖，由现有 npm 锁文件固定版本，后续升级继续核对上游安全公告与渲染策略。

## 旧数据与恢复

存储初始化沿用 SQLite 兼容迁移：仅在 `hosts` 缺少 `lan_ip` 列时，于现有写事务内添加可空列并执行 `lan_ip = name`。原名称及其他资产字段保留；列已经存在时跳过，后续启动不再复制，因此用户编辑或清空局域网 IP 后不会被旧名称覆盖。

本次开发不读取或修改实际运行数据库。部署前应备份资产数据库及对应加密密钥；回退旧应用时可以保留新增列，禁止通过删列或清库丢弃已维护的数据。
