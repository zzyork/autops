# SSH 连接与测试

## 功能范围

主机与跳板机管理页面提供“连接测试”。后端使用保存的资产和凭据建立 SSH 连接，验证服务器身份与登录认证，完成后关闭连接。测试不执行远程命令，不验证 sudo 权限。

- 支持主机直连和单层跳板机 `direct-tcpip` 隧道。
- 主机设置 VIP 时，使用 VIP 作为连接目标；不会在 VIP 失败后改连资产地址。
- 目标机与跳板机独立使用密码或数据库中的 SSH 私钥，两端认证方式可以不同。
- 私钥支持无口令 RSA、Ed25519、ECDSA，兼容资产管理接受的 OpenSSH 和 PEM 格式；解密与格式转换仅在内存中进行。
- 禁用 SSH agent 和运行账号的本地密钥搜索，不使用旧 `key_path`。
- 测试记录持久化到现有 SQLite 数据库；页面显示每项资产最近 20 条记录。

## 使用流程

1. 在主机或跳板机页面保存连接配置；私钥认证须先导入并关联密钥。
2. 点击对应行的“连接测试”，点击“开始测试”。
3. 首次连接会停在“待核对主机密钥”。通过服务器控制台或其他独立可信渠道核对 SHA256 指纹，勾选确认并点击“信任此主机密钥”。
4. 信任后点击“开始测试”重新验证登录；信任动作本身不表示认证成功，也不自动重试。
5. 经由跳板机的首次连接可能需要依次确认跳板机与目标机的身份，每次确认后重新测试。

已知主机密钥发生变化时，连接在用户认证前中止。页面展示原指纹与新指纹，替换信任须再次核对和确认。信任记录按资产类型、资产 ID、实际连接地址和端口保存；同一个跳板机的信任可用于其关联主机。删除资产会清除对应信任记录。

身份确认自测试结束起 10 分钟内有效。确认期间主机、关联跳板机、所选认证密钥的版本发生变化，或当前信任已经被其他确认修改时，服务端拒绝旧确认，需刷新资产或重新测试。浏览器只提交测试 ID，服务端使用该次握手保存的公钥，不接受浏览器指定的替换公钥。

## 测试状态

| 状态 | 含义 |
| --- | --- |
| `queued` | 已接受，等待工作线程 |
| `running` | 正在连接与认证 |
| `succeeded` | 服务器身份校验和登录认证通过 |
| `failed` | 测试未通过 |
| `awaiting_trust` | 服务器身份未知或已变化，认证未继续 |
| `trusted` | 此次身份已确认，仍须重新测试登录 |
| `interrupted` | 后端重新启动时发现未完成记录，或关闭期间未进入执行 |

结果保存实际地址、用户名、所经跳板机名称、阶段、时间和耗时。成功记录说明测试当时能够连接，不代表持续在线。关闭弹窗只停止前端查询，不终止后端测试；再次打开可查看记录并恢复查询。查询失败停止轮询，所选历史记录显示“状态待刷新”，用户通过“刷新记录”恢复查询。

主机列表在倒数第二列“连接状态”（位于“操作”列之前）居中显示一个 SSH 状态图标，直连和经跳板机连接使用相同图标。图标表示最近一次测试状态：灰色圆圈内灰色问号为未测试，绿色圆圈内绿色勾号为通过，红色圆圈内红色叉号为未通过或中断，蓝色圆圈内省略号为查询中、排队或测试中，琥珀色圆圈内感叹号为待核对身份或已信任但需重新测试，灰色圆圈内问号为状态待刷新。圆圈与内部符号使用同一颜色，勾号和叉号以 SVG 线条绘制。悬停或键盘聚焦可查看具体状态和测试时间；查询失败不会被标记为连接失败。列表跟踪尚未完成的测试，弹窗中的测试状态变化同步到列表；关闭弹窗或刷新列表会重新查询状态。

HTTP 请求失败沿用统一“系统异常”提示，页面不展示后端异常详情。测试失败作为已提交任务的结果保存，内部使用认证、超时、连接、配置和系统错误的分类，界面展示“测试未通过”及阶段。

## 执行与部署约束

- 后端每个实例最多 4 个连接测试并发执行，最多接受 16 个未完成测试；同一资产不允许同时提交多个测试。
- 网络连接总时限为 30 秒，覆盖 DNS、TCP、SSH 握手、认证和跳板隧道；TCP、banner 和通道等待上限为 10 秒，认证等待受剩余总时限限制。排队等待不计入连接时限。
- 到期关闭目标连接、隧道及跳板连接。操作系统 DNS 查询无法主动取消，使用最多 4 个无凭据守护线程隔离，不阻塞任务和应用退出。
- 前端通过短请求提交与查询，继续使用现有 8 秒请求超时。
- 当前执行器只支持单实例、单 Uvicorn worker。多 worker 会导致启动恢复与任务去重不一致，不应使用 `--workers` 扩展；需要多实例时另行设计任务协调。
- 当前没有用户认证和权限控制，沿用本机单人运行范围；多人共享或网络开放前需完成相关能力。

## 数据与接口

启动时通过 `backend/app/core/migrations/ssh_connections.py` 新增 `known_host_keys` 和 `ssh_connection_tests` 表，不改写原资产和加密凭据。重启不会自动重试未完成测试。备份仍须同时保存数据库和对应 Fernet 密钥。

测试记录不保存密码或私钥；服务器主机公钥属于身份信息。连接上下文不在对象表示中暴露凭据，日志只记录测试 ID、错误类型和清理失败类型，不打印异常原文。历史记录保留在数据库中，本阶段未提供历史清理操作。

| 方法与路径（前缀 `/api/v1`） | 输入与输出 |
| --- | --- |
| `POST /ssh/connection-tests` | 输入资产类型 `host` / `jump_host`、`target_id`、`version`；返回 202 和测试记录 |
| `GET /ssh/connection-tests?target_type=host&target_id=<ID>` | 最近 20 条记录 |
| `GET /ssh/connection-tests/{test_id}` | 单条测试与当前状态 |
| `POST /ssh/connection-tests/{test_id}/trust` | 无请求体，确认保存的主机密钥；成功返回 204 |

SSH 核心为 `open_ssh_connection(target, jump)` 上下文管理器，供后续远程业务复用；调用结束和建连失败均释放资源。本阶段不包含命令执行、SFTP 操作、自动提权或部署任务。

## 设计取舍与验证

沿用原项目 Paramiko 和单层跳板实现，版本按当前环境与项目依赖规则固定为 `3.5.1`。使用服务层解析资产、仓储层查询记录、路由层提供 HTTP 契约，不将凭据发给浏览器。连接测试使用有限线程执行并保存结果，避免长 HTTP 请求；暂不增加跨任务连接池或外部任务队列。

主机与跳板机复用 `SSHConnectionDialog.vue`：输入为目标资产及显示状态，输出为显示状态变更；依赖统一 API、反馈入口和 Element Plus，局部状态保存在组件内。

本轮在 Python 3.13 环境执行全量 pytest，覆盖本机临时 SSH 协议握手、先校验身份后认证、信任与替换、过期与版本冲突、跳板清理、慢 DNS/TCP/多阶段超时、VIP、旧数据库升级和敏感信息保护；执行前端类型检查与构建。SSH 自检文件遵循现有 `.gitignore`，仅用于本地验证，不纳入索引。未连接真实服务器，未完成浏览器桌面交互验收。
