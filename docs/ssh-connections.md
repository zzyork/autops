# SSH 连接测试

## 批量测试

在主机列表勾选主机并打开“批量测试连接”。弹窗展示目标主机实际连接地址（优先使用 VIP）、端口，以及关联跳板机的名称和地址。范围读取完成后，勾选本次范围确认并点击“开始测试”。

所有新连接测试统一使用**首次自动信任**，没有模式选择：自动保存尚无信任记录的服务器公钥并继续当前连接认证；已有信任记录且公钥不同时仍拦截，不自动覆盖。密钥变化时通过独立渠道核对指纹，在单台详情确认信任后重新测试。

首次自动信任采用首次使用即信任（TOFU），无法识别首次连接中的服务器冒充，只适用于接受该风险的可信网络。主机与跳板机的单台测试同样采用该规则。巡检继续校验已保存的信任，不自行新增或替换信任记录。

共用跳板机的同一公钥并发首次发现时仅新增一次信任；不同公钥竞争时，后到的不同公钥被拦截。弹窗集中展示待核对的新旧指纹，并合并同一跳板机的相同候选指纹。

“本次新增信任”统计实际新建的服务器身份，包含跳板机。保存信任与认证成功是两个结果：认证失败或连接超时仍保留已经提交的信任，测试结果仍为未通过。单台历史详情显示策略、新增身份及指纹。

关闭批量弹窗会停止后续提交，已经提交的测试继续执行；关闭不撤销已保存的信任。

## 接口与持久化

`POST /api/v1/ssh/connection-tests` 可选字段 `host_key_policy` 仅接受 `accept_new`，省略时同样采用该规则；提交 `strict` 返回 422。响应保留 `host_key_policy` 和 `auto_trusted_keys`；每个新增身份含资产类型、ID、地址、端口、密钥类型、SHA256 指纹及值为 `null` 的原指纹。历史记录仍可返回 `strict`，详情显示为“人工确认（历史记录）”，不代表可以创建该模式的新测试。

自动信任在用户认证前通过独立数据库事务完成，复核资产与凭据快照，并重新检查当前信任。锁等待按 SSH 剩余时限限制，检查到过期或持久化失败时不会继续认证；数据库锁等待超时的未提交事务会回滚。磁盘提交不是硬实时操作，超时结果不代表此前已经提交的信任被撤销，应查看新增信任记录。旧数据库由启动迁移补齐字段，旧测试记录的策略为严格校验、新增信任为空。
