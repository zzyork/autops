# 主机巡检

巡检通过已有主机资产的 SSH 配置执行固定的只读 Linux 命令，按主机保存检查结果到 SQLite。不支持自定义远程命令，不会自动使用 `sudo`；目标需允许当前登录账号执行所选检查的命令，并具备 `bash` 及对应的 `hostname`、`ip`、`df`、`ps`、`systemctl` 等工具或 `/proc` 数据。缺少工具或输出不符合预期时按实际检查结果报错，不以备用数据替代。巡检前先在“主机管理”（使用跳板机时也检查对应跳板机）进行连接测试，独立核对服务器指纹并确认信任；未确认或密钥变化时不会绕过 SSH 身份校验，巡检主机会失败。连接测试本身只验证 SSH 登录，不执行巡检命令。

## 页面使用

1. 打开侧栏“巡检任务”或访问 `/inspections`，点击“创建巡检”。
2. 填写名称，在分组筛选后的主机列表中选择 1-32 台已保存主机，至少选择一项检查。默认选中全部四项；仅针对主机资产，连接方式沿用其直连、VIP 或单层跳板配置。创建时会校验资产版本；资产变更后请刷新再提交，排队期间凭据或连接资产变更也可能使该主机执行失败。
3. 创建单次任务时不可调整巡检规则；后端使用统一默认阈值、执行时限和服务配置，并保存本次规则快照。提交后任务后台执行，关闭弹窗不取消任务。同一主机已有巡检占用时新任务被拒绝；队列不可用也会拒绝创建。
4. “巡检任务”列表按创建时间倒序分页（每页 20 条），显示执行进度；点击任务名称或“查看记录”跳转到“巡检记录”（`/inspections/records`）。记录页查看各主机、各检查的执行状态、风险结论、指标、表格、发现和本次规则快照；活跃任务在页面中轮询，失败后可手动刷新/重试。任务结束后可点击“导出报告”，下载 Markdown 文件。
5. “巡检规则”（`/inspections/rules`）集中展示检查项、默认资源阈值、执行时限和服务判定配置。当前为只读页面，没有提供规则修改或保存接口。

没有提供取消、删除历史或自动清理历史的操作。历史记录随数据库保留；备份、访问与容量管理需由部署方负责。

## 检查内容与判定

| 检查项 | 采集与限制 |
| --- | --- |
| 系统基础信息 `server_info` | 主机名、`/etc/os-release` 的 `PRETTY_NAME`、内核、`/proc/uptime` 与 IPv4/IPv6 网卡地址。 |
| 系统资源 `system_resources` | `/proc/stat` 间隔约 1 秒采样 CPU；`/proc/loadavg` 的 1/5/15 分钟负载；`/proc/meminfo` 的内存、Swap；`df -PT -k` 磁盘；按 CPU/内存排序的进程 TOP10（仅进程名，不采集完整命令行参数）。 |
| 服务状态 `service_status` | 对配置的 systemd 候选单元依次执行 `systemctl show`，读取加载和运行状态；不会启动或修复服务。 |
| 网络信息 `network_info` | 网卡 IPv4/IPv6 地址与 `ss` 读取的本机 TCP LISTEN、UDP UNCONN 监听信息；不测试外部网络可达性。`ss` 缺失时监听采集标为不适用，地址仍可显示。 |

CPU 使用率按两次 `/proc/stat` 总量增量减去 idle 和 iowait 增量计算，即 **busy 包含非 idle、非 iowait 的时间**；guest 已计入 user/nice，不重复累加。旧 Python 实现使用 `vmstat` 的 `100 - id`，包含 iowait，新口径排除 iowait，因此有 I/O 等待时数值可能更低，旧告警结果不能直接视为等价。内存使用率为 `(MemTotal - MemAvailable) / MemTotal`，与旧的已用内存口径可能不同。负载直接展示原始 1/5/15 分钟值，不按 CPU 核数归一化，也不参与阈值判定。无 Swap 时使用率为 `null`（界面不显示为 0%），不产生 Swap 阈值告警。

磁盘排除 `tmpfs`、`devtmpfs`、`proc`、`sysfs`、`cgroup`、`cgroup2`、`devpts`、`securityfs`、`debugfs`、`tracefs`、`configfs`、`pstore`、`mqueue`、`hugetlbfs`、`autofs` 等伪文件系统，剩余每个挂载点按 `df` 的使用率独立判定；没有任何可监控磁盘时资源检查失败（`no_monitored_disks`），不会返回正常。CPU、内存、磁盘、Swap 默认警告/严重阈值分别为 80/95、80/95、80/90、50/80（%），达到阈值即触发对应发现；阈值范围 0-100%，警告不得高于严重。

默认服务共 17 项：`sshd`、`crond`、`chronyd`、`firewalld`、`NetworkManager`、`nginx`、`mysqld`、`redis`、`rabbitmq`、`docker`、`minio`、`supervisord`、`prometheus`、`node-exporter`、`mysqld-exporter`、`keepalived`、`DmServiceDMSERVER`。其中部分项目有多个候选单元名称，具体列表以 `GET /api/v1/inspections/catalog` 的默认配置为准。默认都为可选，创建单次任务不可修改。未找到的可选服务显示“未安装”，不算正常运行：若全部未找到，服务检查结论为“不适用”；若部分已找到且状态正常，整体可能为“正常”，但不代表其余可选服务正在运行。规则中的必需服务未安装则为“警告”，已找到但未加载或未运行的服务也产生警告。默认 `docker` 仅检查服务状态，不代表提供 Docker 管理模块。

执行状态（排队、执行中、完成、部分完成、失败、中断，以及检查项的跳过）与风险结论（正常、警告、严重、不适用、无法判定）是两回事。`completed` 只表示指定检查执行完，不保证主机健康；任何检查失败、跳过或中断都不能当作健康正常。某项检查采集失败后其他检查通常继续；SSH 断连或主机时限到达则跳过剩余检查，不自动重连或补跑。

## 执行边界与故障

- 单任务最多 32 台主机。单实例巡检执行器有 4 个工作线程，最多容纳 64 个已提交但未结束的主机执行（包括运行中和排队中）；同一主机不并发执行两个巡检。
- 单命令时限 2-120 秒，单主机时限 10-600 秒，默认分别为 30 秒与 180 秒，且单命令时限不能大于单主机时限。SSH 建连使用 `min(30 秒, 配置的单主机时限)` 的连接时限；主机执行时限也覆盖后续检查。超时会关闭本地 SSH channel/连接并标记失败或跳过，不承诺终止远端已启动的进程。
- 单条命令 stdout 与 stderr **合计**最多 256 KiB；结果表最多 256 行，单元格最多 500 字符。超限明确失败（`output_limit`），没有截断后继续当作成功的兜底。
- 写库故障会阻止后续任务创建及列表/详情/报告查询（503）；恢复数据库并重启服务后，先前未结束项标为中断，不会自动远程重试。服务关闭会停止接受新任务并等待当前短操作结束，取消尚未启动的排队操作，随后将未结束记录标为中断；不能视为远端进程已被强制杀死。
- 任务队列和工作线程位于进程内，仅支持单后端实例、单 Uvicorn worker；不要用 `--workers` 或多实例共享数据库来扩容巡检。

## 接口、数据与报告

所有接口前缀为 `/api/v1/inspections`：

| 方法与路径 | 作用 |
| --- | --- |
| `GET /catalog` | 返回四类检查定义与默认配置。 |
| `POST /tasks` | 以 JSON 提交 `name`、`hosts: [{id, version}]`、`checks`；不接受 `config`，额外字段返回 HTTP 422。后端保存统一默认规则快照，成功返回任务详情及 HTTP 202。 |
| `GET /tasks?limit=20&offset=0` | 返回摘要、总数；`limit` 范围 1-50，`offset` 不小于 0。 |
| `GET /tasks/{task_id}` | 返回任务配置、主机与检查详情。 |
| `GET /tasks/{task_id}/report` | 任务终态可用；进行中返回 409。返回 JSON `{filename, content}`，**不是**直接下载文件的流。 |

前端将报告 JSON 的 `content` 转为本地 Markdown 下载；服务端按任务 UUID 生成 `inspection-{任务 UUID}.md` 文件名，不接受或持久化用户指定的文件名、下载路径，报告内容也不作为单独文件存储。报告对表格/字段文本做 Markdown 转义，对原样 JSON 配置使用按内容动态加长的代码围栏；本次规则快照原样列入报告。任务和检查记录不保存 SSH 密码、私钥或完整进程命令行参数，但会保存主机名、地址、端口、登录用户、分组、指标及配置；**不保证对这些字段做额外敏感信息脱敏**，报告和数据库均应按运维数据管控访问。

此功能基于现有资产、SSH 凭据与信任数据，不提供身份认证、权限控制或操作审计；对外开放服务前须另外落实访问控制。当前说明按源码核对；本轮未在浏览器或真实服务器上验证巡检流程。
