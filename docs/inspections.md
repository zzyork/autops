# 主机巡检

巡检通过已有主机资产的 SSH 配置执行固定的只读 Linux 命令，按主机保存检查结果到 SQLite。不支持自定义远程命令，不会自动使用 `sudo`；目标需允许当前登录账号执行所选检查的命令，并具备 `bash` 及对应的 `hostname`、`ip`、`df`、`ps`、`systemctl`、`journalctl`、`readlink`、`grep`、`tail` 等工具或 `/proc` 数据。缺少工具或输出不符合预期时按实际检查结果报错，不以备用数据替代；日志检查中缺少 journalctl 或目标日志文件则按来源标记不适用，缺少 readlink 则检查失败。巡检前先在“主机管理”（使用跳板机时也检查对应跳板机）进行连接测试，独立核对服务器指纹并确认信任；未确认或密钥变化时不会绕过 SSH 身份校验，巡检主机会失败。连接测试本身只验证 SSH 登录，不执行巡检命令。

## 页面使用

1. 打开侧栏“巡检任务”或访问 `/inspections`，点击“创建巡检”。
2. 填写名称，在分组筛选后的主机列表中选择 1-32 台已保存主机，至少选择一项检查。默认选中全部五项；仅针对主机资产，连接方式沿用其直连、VIP 或单层跳板配置。创建时会校验资产版本；资产变更后请刷新再提交，排队期间凭据或连接资产变更也可能使该主机执行失败。
3. 创建单次任务时不可单独调整巡检规则；后端读取当前统一规则的阈值、执行时限、服务和日志配置，并保存本次规则快照。提交后任务后台执行，关闭弹窗不取消任务。同一主机已有巡检占用时新任务被拒绝；队列不可用也会拒绝创建。
4. “巡检任务”列表按创建时间倒序分页（每页 20 条），显示执行进度。侧栏“巡检记录”（`/inspections/records`）默认只列出已结束的历史记录；点击记录名称后，显示该任务概览、全任务严重/警告数量及 AI 汇报，不同时展开历史列表。点击“返回历史记录”返回列表；任务页的“查看记录”也可直接打开指定任务，活跃任务在概览中轮询进度。
5. 记录概览的“巡检记录详情”按钮进入 `/inspections/records/{任务ID}`，选择本次任意服务器查看检查完成数和严重/警告发现数，按检查项展开或折叠状态、结论、指标、表格及发现；详情页不展示规则配置，可返回所选记录的汇报页。任务结束后可在详情页“导出报告”下载原始 Markdown 文件，汇报页可另行导出 AI 汇报文本。历史列表可以确认删除已结束记录；任务、主机结果、检查结果及 AI 报告级联删除，不可撤销。删除时取消该任务的 AI 生成，停止后续模型请求；已经发出的请求和数据无法追回。
6. “巡检规则”（`/inspections/rules`）集中展示检查项、当前资源阈值、执行时限、服务及日志配置；点击“编辑规则”可修改阈值、时限、服务和日志扫描范围并保存。规则保存在 `AUTOPS_DATA_DIR/inspection-rules.json`（默认 `backend/runtime/inspection-rules.json`），无文件时使用内置默认规则；旧规则文件缺少日志字段时使用内置日志默认值。保存使用同目录临时文件并原子替换。保存成功仅影响之后创建的任务，已有任务的规则快照和报告不随之变化。文件损坏时读取规则和创建任务会失败，不会静默恢复默认配置。

没有提供取消任务或自动清理历史的操作。未删除的历史记录随数据库保留；备份、访问与容量管理需由部署方负责。备份规则时同时备份数据库及对应密钥。

## AI 汇报

新巡检任务整体结束后，自动使用主模型分析已保存记录。主模型须通过对话测试，纯文本分析不要求工具测试通过；未配置或测试未通过时保存“不可用”状态，巡检执行结果不受影响。历史任务不会批量补跑，可以在所选记录页手动“生成 AI 汇报”；成功报告保存在 SQLite，重新生成失败仍保留上次成功版本，页面分别显示本轮状态和报告的模型、时间。主模型资格检查与报告认领在同一事务中完成；已受理批次固定使用当时的模型地址、名称、凭据与配置版本快照，后续模型配置变更影响下一批生成。

分析覆盖任务所有主机、严重/警告发现、异常结论、未完成检查以及保存的每条错误日志，并按来源保留证据编号。“全部”仅指本次任务保存的数据，不包括采集范围外日志；结果序号不是服务器原始文件行号。输入包含资源指标、服务状态、日志扫描规则、来源状态及采集时间。请求按最多 40 条证据、约 24000 个序列化字符分批，长上下文按完整片段拆分，不静默截断。模型必须返回 JSON 和完整证据引用；覆盖缺失、引用越界、严重级别降低、响应截断或任一批失败都不会发布本轮报告。总体汇报可分层汇总，但问题明细和证据完整保留。覆盖校验不能证明模型自由文本的事实准确性，根因推断与建议需结合原始记录人工核对。

报告展示总体分析、严重问题、警告、日志问题、未完成检查、判定范围限制及可折叠证据；未完成、不适用和结论未知的检查必须进入证据引用校验，并通过独立分区说明其限制，不能当作健康依据。模型建议不会执行 SSH 命令。**已保存的日志原文、主机名、地址、资源及服务数据将发送给已配置的模型服务**，没有新增日志脱敏功能；部署方须按运维数据选择模型服务及访问权限。页面以文本插值展示，不渲染模型 HTML。

AI 执行器有 2 个线程，最多 8 个已提交但未结束的生成任务；单次模型调用最长 300 秒，一份报告总时限 1800 秒。队列满、模型不可用、生成失败或超时均明确记录状态，不自动重试或切换备用模型，可手动重新生成。重启后未结束生成标为“已中断”，不会自动补跑。AI 持久化故障阻止报告接口继续展示陈旧状态，原始巡检查询和执行保留独立的可用状态。迁移幂等创建 `inspection_ai_reports` 表，不改写既有检查结果。

## 检查内容与判定

| 检查项 | 采集与限制 |
| --- | --- |
| 系统基础信息 `server_info` | 主机名、`/etc/os-release` 的 `PRETTY_NAME`、内核、`/proc/uptime` 与 IPv4/IPv6 网卡地址。 |
| 系统资源 `system_resources` | `/proc/stat` 间隔约 1 秒采样 CPU；`/proc/loadavg` 的 1/5/15 分钟负载；`/proc/meminfo` 的内存、Swap；`df -PT -k` 磁盘；按 CPU/内存排序的进程 TOP10（仅进程名，不采集完整命令行参数）。 |
| 服务状态 `service_status` | 对配置的 systemd 候选单元依次执行 `systemctl show`，读取加载和运行状态；结果表不展示未安装服务，不会启动或修复服务。 |
| 网络信息 `network_info` | 网卡 IPv4/IPv6 地址与 `ss` 读取的本机 TCP LISTEN、UDP UNCONN 监听信息；监听表过滤回环地址，不测试外部网络可达性。`ss` 缺失时监听采集标为不适用，地址仍可显示。 |
| 错误日志 `log_error` | 以 `journalctl --since` 查询最近指定天数的 `err..alert` 日志，排除 `systemd-coredump`、`ldapdb_canonuser_plug_init`（不区分大小写）；配置的文件路径用 `grep -aiE` 匹配 `error|failed|fatal|panic|crit|critical|异常`。各来源最多展示最近指定行数。 |

CPU 使用率按两次 `/proc/stat` 总量增量减去 idle 和 iowait 增量计算，即 **busy 包含非 idle、非 iowait 的时间**；guest 已计入 user/nice，不重复累加。旧 Python 实现使用 `vmstat` 的 `100 - id`，包含 iowait，新口径排除 iowait，因此有 I/O 等待时数值可能更低，旧告警结果不能直接视为等价。内存使用率为 `(MemTotal - MemAvailable) / MemTotal`，与旧的已用内存口径可能不同。负载直接展示原始 1/5/15 分钟值，不按 CPU 核数归一化，也不参与阈值判定。无 Swap 时使用率为 `null`（界面不显示为 0%），不产生 Swap 阈值告警。

磁盘排除 `tmpfs`、`devtmpfs`、`proc`、`sysfs`、`cgroup`、`cgroup2`、`devpts`、`securityfs`、`debugfs`、`tracefs`、`configfs`、`pstore`、`mqueue`、`hugetlbfs`、`autofs` 等伪文件系统，剩余每个挂载点按 `df` 的使用率独立判定；没有任何可监控磁盘时资源检查失败（`no_monitored_disks`），不会返回正常。CPU、内存、磁盘、Swap 默认警告/严重阈值分别为 80/95、80/95、80/90、50/80（%），达到阈值即触发对应发现；阈值范围 0-100%，警告不得高于严重。

内置默认服务共 17 项：`sshd`、`crond`、`chronyd`、`firewalld`、`NetworkManager`、`nginx`、`mysqld`、`redis`、`rabbitmq`、`docker`、`minio`、`supervisord`、`prometheus`、`node-exporter`、`mysqld-exporter`、`keepalived`、`DmServiceDMSERVER`。其中部分项目有多个候选单元名称，当前生效配置以 `GET /api/v1/inspections/catalog` 返回的 `defaults` 为准。内置默认都为可选；可在规则页调整是否必需、候选单元和服务列表（最多 30 项），创建单次任务不可修改。未安装服务不出现在结果表中：若全部未找到，服务检查结论为“不适用”；若部分已找到且状态正常，整体可能为“正常”，但不代表其余可选服务正在运行。必需服务未安装仍产生警告发现并将结论标为“警告”；已找到但未加载或未运行的服务也产生警告。默认 `docker` 仅检查服务状态，不代表提供 Docker 管理模块。

网络监听表排除 `127.0.0.0/8`、`::1` 及映射到 `127.0.0.0/8` 的 IPv6 地址（如 `[::ffff:127.0.0.1]:80`），保留 `0.0.0.0`、`[::]` 和非回环地址；“本机监听数量”与可见表行数一致。新任务采集时过滤，已有历史记录在详情及报告的响应中也按同一规则过滤；原有数据库负载不因展示过滤而改写。此过滤仅针对监听表，不是网卡地址表。

日志规则默认最近 30 天、每来源最多 200 行，默认文件路径为 `/var/log/messages`、`/var/log/secure`、`/var/log/nginx/error.log`、`/var/log/mysql/error.log`、`/var/log/mysqld.log`、`/var/log/rabbitmq/rabbitmqd-error.log`。可配置天数 1-365、行数 1-200、最多 12 条 `/var/log/` 下不重复的规范路径（每条最多 240 字符，不允许控制字符、空路径段或 `.`/`..` 路径段）；空路径列表表示仅查询 journal。路径经过服务端校验及 shell 引用；远端逐级检查父目录的存在性和搜索权限，再用 `readlink -e` 解析实际路径，只有实际路径仍在 `/var/log/` 下且为可读普通文件才扫描。缺少 readlink、符号链接越界、悬空链接及权限不足会使检查失败。每来源展示“匹配”“未匹配”“不适用”状态；无 journalctl 或确认文件不存在为不适用，全部不可用时总体不适用，至少一个可用且无匹配为正常，有匹配为警告。命令失败和超限会令该检查失败，不会伪装成无匹配或不适用。不会自动提权；结果表和报告可能含敏感日志原文，须控制访问和保留周期。文件检查没有时间过滤，仅 journal 使用最近天数。

执行状态（排队、执行中、完成、部分完成、失败、中断，以及检查项的跳过）与风险结论（正常、警告、严重、不适用、无法判定）是两回事。`completed` 只表示指定检查执行完，不保证主机健康；任何检查失败、跳过或中断都不能当作健康正常。某项检查采集失败后其他检查通常继续；SSH 断连或主机时限到达则跳过剩余检查，不自动重连或补跑。

## 执行边界与故障

- 单任务最多 32 台主机。单实例巡检执行器有 4 个工作线程，最多容纳 64 个已提交但未结束的主机执行（包括运行中和排队中）；同一主机不并发执行两个巡检。
- 单命令时限 2-120 秒，单主机时限 10-600 秒，默认分别为 30 秒与 180 秒，且单命令时限不能大于单主机时限。SSH 建连使用 `min(30 秒, 配置的单主机时限)` 的连接时限；主机执行时限也覆盖后续检查。超时会关闭本地 SSH channel/连接并标记失败或跳过，不承诺终止远端已启动的进程。
- 单条命令 stdout 与 stderr **合计**最多 256 KiB；结果表最多 256 行，单元格最多 500 字符。超限明确失败（`output_limit`），没有截断后继续当作成功的兜底。
- 写库故障会阻止后续任务创建及列表/详情/报告查询和任务删除（503）；恢复数据库并重启服务后，先前未结束项标为中断，不会自动远程重试。服务关闭会停止接受新任务并等待当前短操作结束，取消尚未启动的排队操作，随后将未结束记录标为中断；不能视为远端进程已被强制杀死。
- 任务队列和工作线程位于进程内，仅支持单后端实例、单 Uvicorn worker；不要用 `--workers` 或多实例共享数据库来扩容巡检。

## 接口、数据与报告

所有接口前缀为 `/api/v1/inspections`：

| 方法与路径 | 作用 |
| --- | --- |
| `GET /catalog` | 返回五类检查定义与当前生效配置 `defaults`（`InspectionCatalog`）；没有规则文件时使用内置默认配置。 |
| `PUT /catalog` | 请求体为完整配置（`thresholds`、`services`、`logs`、`command_timeout_seconds`、`host_timeout_seconds`），须提供全部阈值字段、每项服务的 `name`、`candidates`、`required` 及日志的 `days`、`lines`、`paths`；服务端校验后原子保存到数据目录，最后一次成功保存生效。成功返回更新后的 `InspectionCatalog`（200），参数无效或缺字段返回 422。只影响新任务。 |
| `POST /tasks` | 以 JSON 提交 `name`、`hosts: [{id, version}]`、`checks`；不接受 `config`，额外字段返回 HTTP 422。后端保存创建时生效的规则快照，成功返回任务详情及 HTTP 202。 |
| `GET /tasks?limit=20&offset=0&records_only=true` | 返回摘要、总数；`limit` 范围 1-50，`offset` 不小于 0。`records_only=true` 在统计与分页前筛选已结束任务；省略或为 false 时包含所有任务。 |
| `GET /tasks/{task_id}` | 返回任务配置、主机与检查详情。 |
| `DELETE /tasks/{task_id}` | 仅删除已结束任务（完成、部分完成、失败或中断），并级联删除主机执行与检查结果；成功返回 204（无响应体），任务不存在返回 404，排队/执行中返回 409，ID 格式无效返回 422；巡检记录持久化不可用时返回 503。 |
| `GET /tasks/{task_id}/report` | 任务终态可用；进行中返回 409。返回 JSON `{filename, content}`，**不是**直接下载文件的流。 |
| `GET /tasks/{task_id}/analysis` | 返回 AI 生成状态、模型/时间、已保存报告及 `can_generate`。无历史报告返回明确的 `not_generated`，不是成功生成的空报告。不存在 404、ID 无效 422、AI 持久化不可用 503。 |
| `POST /tasks/{task_id}/analysis` | 无请求体；认领结束任务的生成，返回状态和 202。巡检未结束、正在生成或主模型不可用返回 409；队列/持久化不可用返回 503。生成失败不自动重试。 |

前端将报告 JSON 的 `content` 转为本地 Markdown 下载；服务端按任务 UUID 生成 `inspection-{任务 UUID}.md` 文件名，不接受或持久化用户指定的文件名、下载路径，报告内容也不作为单独文件存储。报告对表格/字段文本做 Markdown 转义，对原样 JSON 配置使用按内容动态加长的代码围栏；本次规则快照原样列入报告，即使记录详情页不展示配置也可从详情接口和报告获取。删除任务后报告接口返回 404。任务和检查记录不保存 SSH 密码、私钥或完整进程命令行参数，但会保存主机名、地址、端口、登录用户、分组、指标及配置；**不保证对这些字段做额外敏感信息脱敏**，报告和数据库均应按运维数据管控访问。

此功能基于现有资产、SSH 凭据与信任数据，不提供身份认证、权限控制或操作审计；对外开放服务前须另外落实访问控制。当前说明按源码核对；本轮未在浏览器或真实服务器上验证巡检流程。
