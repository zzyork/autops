# 巡检 AI 报告单次请求方案

2026-10-13 更新：日志合并与逐条分析粒度已由[诊断组方案](2026-10-13-inspection-diagnostic-groups.md)替代。当前按诊断组发送紧凑输入，每组一次分析，全部原文和位置留在报告证据中；以下内容记录此前方案。单次请求、无自动重试、严格覆盖和失败保留旧成功报告的边界继续沿用。

用户已确认将全部合并错误日志一次提交给 AI，按固定格式返回逐条原因与处理建议，由后端校验并组装报告。

- 输入沿用按主机、来源及忽略行首时间戳的正文合并逻辑，保留编号、正文、发生次数、时间范围及原始序号。长日志证据片段先完整还原，再放入同一请求；不额外上传附件。
- 有合并日志时只发起一次模型请求，不分批、不自动重试、不请求二次汇总。无匹配日志时不调用模型，直接组装已有巡检事实。
- 输出为纯 JSON，包含 `issues` 数组；每项只包含 `evidence_id`、`severity`、`analysis`、`recommendation`。每个输入编号恰好对应一个结果。后端校验格式、等级、正文长度和编号完整性，按原顺序关联日志来源与正文。
- 输出预算从 2048 tokens 起，按 `256 + 日志数 × 384` 增长，最高为既有 provider 上限 8192 tokens。该预算是启发式分配，不保证任意数量日志都能输出完整结果。
- 巡检报告请求体单独设置为最多 1000000 字符，普通对话默认仍为 128000 字符；超限错误记录实际字符数和上限，不输出日志正文。字符限额是程序保护边界，不代表模型的 token 容量。响应正文 65536 字符、巡检流响应 16 MiB（普通对话默认 256000 字节）；流计量包含事件包装及模型附加字段，超限同时记录累计流字节与已解析正文字符数，不记录内容。总请求时限 300 秒，单次读取时限 60 秒。输入超限、网络失败、输出截断或编号不完整均明确失败，不截断输入或保存部分结果。实际模型的上下文及输出限制仍由其服务端校验。
- 复用现有后台执行器、模型快照、报告持久化与接口，无数据库迁移。历史报告保持可读；生成失败仍保留上次成功报告。
- 进度接口保留现有字段，当前生成只报告一次全量分析；前端展示当前步骤和开始时间。

修改涉及分析引擎、provider 输出上限常量和报告组件文案。遵循两份开发规范，复用现有分层、类型、请求封装和错误处理，不新增依赖或失败兜底。

验证覆盖多于五条日志的单次调用、长日志还原与证据关联、JSON/编号校验、网络失败不重试、输入超限不发送、输出截断不保存、取消、无日志跳过模型，以及两种流式模型协议。实际在线模型耗时需另行测量。
