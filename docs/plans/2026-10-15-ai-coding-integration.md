# AI 编程规范与技能接入计划

目标：让 OpenCode 与 Codex 共享经过审核、可追溯的项目级技能，使外部技术知识按本项目规范用于开发和审核。

方案：继续由根目录 `AGENTS.md` 引导完整阅读三份规范；在 `.agents/skills/` 保存固定提交的 Vue、FastAPI 原文快照，以及项目编写的前端、后端和变更审核技能。OpenCode 增加规划、审核两个命令入口，Codex 通过技能名称调用。复用 `docs/plans/` 记录较大需求的行为、契约、步骤和验收。

技术范围：Markdown、Agent Skills 格式、现有 OpenCode 命令机制。业务技术栈、运行依赖及数据库不在此次修改范围内。

## 方案取舍

| 方案 | 收益 | 成本与结论 |
| --- | --- | --- |
| 仅增加规则链接 | 改动少 | 缺少可离线读取的知识和明确任务入口，不足以完成接入 |
| 规则入口、固定技能快照、项目适配技能 | 复用客户端原生机制，来源和冲突可审核 | 需要手动审核更新；本次采用 |
| 同时安装规格框架、分发器、流程插件和 MCP | 可覆盖更多协作场景 | 当前已有任务文档和流程技能，重复维护且增加配置与服务成本；待实际需求出现后单独评估 |

## 实施步骤

1. 核对三份规范、现有工作区修改、依赖清单、请求封装和数据库依赖；保留原有未提交工作。
2. 从官方原仓库的固定提交读取 Vue、FastAPI 技能全部文件，审核内容与适用许可，再用纯文档快照落地。保留上游原文及相对参考文件，不执行其安装示例。
3. 新增 `autops-frontend`、`autops-backend`、`autops-review`，组织本项目的源码定位、知识加载、契约检查和现有验证命令，避免复制三份规范全文。
4. 新增 `docs/AI-编程接入指南.md`，集中维护来源提交、适用范围、已知冲突、触发示例、更新步骤和验证边界。
5. 向 `AGENTS.md` 增量加入技能路由和外部知识适用边界；新增 `.opencode/commands/autops-plan.md`、`autops-review.md` 及拒绝编辑、Shell 和任务委派的 `.opencode/agents/autops-auditor.md`；更新文件索引。技能每任务加载一次，独立审核不回调实施或审核。
6. 校验技能元数据、名称、相对链接、上游文件完整性与 Git blob 哈希，以及工作区差异；独立审核后修复问题。

## 授权与风险

- 本次用户已授权规划并接入；无需再为常规文件新增逐项确认。未来架构调整、迁移、新依赖和兜底继续按项目约定处理。
- 上游代码示例含 `any`、直接请求、移动端条件或不同库偏好，项目适配技能和入口必须明确禁止据此改变项目要求。
- 固定上游提交只保证可追溯，不保证所有 API 适用于当前安装版本。实现前核对实际依赖，不能自动升级或重写。
- 上游技能是参考知识，不获得优于项目规范或用户指令的地位。出现未解决的实质冲突时，先说明再处理受影响部分。
- 不生成规则副本或自动更新任务；上游更新由维护者显式发起，并重新审核完整差异。

## 验收

- 五个技能均符合目录与元数据格式，内部参考链接有效，两个上游快照包含许可和全部目录文件。
- 前端任务加载项目前端技能与 Vue 知识，后端任务加载项目后端技能与 FastAPI 知识，跨端任务检查两侧契约，完成后执行变更审核。
- OpenCode 规划命令只输出方案和计划，审核命令只输出发现，不暗含业务实施、提交或推送授权。
- 本次只改文档与 Agent 入口，执行结构、来源和一致性检查；不以应用测试证明技能加载。
- 当前终端未发现 OpenCode/Codex 可执行命令，不能宣称已通过客户端实际发现或模型触发测试；在接入指南和最终说明中给出重启与验证方法。
