# AI 功能独立模型配置

## 目标与已确认行为

当前使用 AI 的业务为对话式运维和巡检 AI 汇报。新增两个独立配置，选择已有模型连接；用户确认未指定时沿用主模型。指定连接失效时直接拒绝操作，不切换到主模型或备用模型。

- AI 对话与运维工具使用同一会话模型；功能配置仅影响新会话。
- 巡检 AI 汇报的自动和手动生成使用同一功能配置；已认领批次固定使用模型快照。
- 普通文本对话保持既有能力规则；运维工具仍要求对话与工具测试均通过，汇报仅要求对话测试通过。

## 实现与接口

沿用巡检规则的 JSON 文件和原子替换模式，在数据目录保存 `ai-feature-models.json`，不修改数据库结构。

`GET /api/v1/ai/feature-models` 读取配置，`PUT /api/v1/ai/feature-models` 全量保存并返回配置：

```json
{
  "chat_connection_id": null,
  "inspection_report_connection_id": null
}
```

两个字段均必填，值为正整数连接 ID 或 `null`。首次尚未保存配置时，两个功能均沿用主模型。保存时检查连接存在性，功能引用的连接禁止删除；已有会话引用保护保持生效。配置写入与连接删除在进程内共用锁。

后端配置服务负责读取、校验、保存及选模；路由提供配置接口和会话选模，巡检报告执行器使用同一选模服务。

前端 `FeatureModelsForm.vue` 接收连接列表及加载状态，经既有 API 层读写配置，并通过 `configured` 事件上报已保存配置或不可用状态。表单复用既有布局与 Element Plus 控件；请求错误通过统一反馈入口提示。加载失败时禁止保存和删除连接，保存失败保留草稿。新建会话及创建前刷新功能配置与连接，已有会话仍使用自身绑定连接。

## 风险与错误处理

独立选择模型不保证供应商模型具备业务所需能力，仍受现有测试与响应校验约束。更改连接的模型、协议等字段仍使原会话版本失效。

配置缺失表示尚未设置；文件损坏、不可读或字段不完整返回配置错误，不当作默认配置，不设置报告持久化故障标记。修复配置后无需重启即可恢复。
