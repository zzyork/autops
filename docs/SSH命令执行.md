# SSH 命令流程与实时输出

## 使用方式

从控制台主导航进入“SSH 执行”，创建流程并选择一台已有主机。按顺序添加步骤，每步填写名称、完整命令、预期退出码和时限。业务验收也作为步骤编写，例如启动服务后增加服务状态或健康检查。提交前确认目标与步骤；首次连接或服务器公钥变化时继续使用统一身份确认。

每一步使用独立的 SSH Channel 和 Shell，同一流程复用已验证的 SSH 连接。上一条命令的 `cd`、Shell 变量不会自动传入下一步。命令作为完整脚本块执行，不按换行或分号拆分；复合命令和管道需自行正确传播退出状态。执行器不自动加载 profile、提权、申请 PTY 或接受交互输入。

执行记录提供分页、步骤详情、纯文本 stdout/stderr、真实退出码、起止时间和必要停止原因。选择记录后实时接收后续事件；页面隐藏或关闭只结束订阅。再次激活页面或手动“刷新结果 / 继续查看”会读取一致的详情，再从其事件序号继续查看。请求失败不自动重提命令、不自动重连输出流。

## 成功、失败与未知结果

默认预期退出码为 `0`，可为具体命令设置其他允许值，例如将特定检测命令的“未发现”作为已定义结果。stderr 有内容不等于执行失败。只有取得有效退出码、满足步骤约定并保存结果后才会开始下一步；验收步骤失败同样终止流程。

| 状态 | 含义 |
| --- | --- |
| `queued` | 尚未执行，等待调度或前序步骤 |
| `running` | 正在连接或执行 |
| `succeeded` | 流程或步骤满足其成功条件 |
| `failed` | 已确认不能按要求完成，例如预期退出码不符、派发失败或执行时限已超出 |
| `unknown` | 命令可能已执行，但未取得可信退出结果 |
| `skipped` | 仅步骤使用；前置条件未满足，未执行 |

收到 `-1` 表示没有有效退出状态，不计为成功。命令尝试发送之后发生超时、断连或采集中断且没有有效退出码时，记录为 `unknown`，剩余步骤标为 `skipped`。已取得的退出码不会因后来断连而丢失；后续连接已不可用时停止流程，不自动重连。超时即使携带已知退出码也停止推进，记录超时及实际退出码。

停止采集或关闭 SSH 通道不证明远端进程已经退出，也不证明之前的变更已撤销。此功能不自动重试、恢复执行或补偿。流程所需的验收、备份和恢复必须由业务明确设计；未确认结果前不能自动重新执行或回退。

## 接口契约

接口位于 `/api/v1/ssh/executions`，请求错误沿用项目的 HTTP 状态与 `detail` 契约，前端仍通过统一入口显示“系统异常”。执行结果中的稳定 `error_code` 与请求错误分别处理，已知停止原因映射为有限的中文业务说明，不展示底层异常原文。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /ssh/executions` | 创建一次流程，返回 202 和详情 |
| `GET /ssh/executions?page=1&page_size=10` | 分页读取摘要，页长为 10/20/50/100 |
| `GET /ssh/executions/{id}` | 读取同一快照中的状态、步骤输出与 `sequence` |
| `GET /ssh/executions/{id}/events?after=N` | 只读取序号大于 N 的事件，永不启动命令 |
| `DELETE /ssh/executions/{id}` | 显式删除终态业务记录、步骤和全部输出；运行中返回 409 |

创建正文包含：

- `id`：客户端为一次新意图生成的 UUID。
- `name`：去除首尾空白后 1–100 字符的流程名称。
- `host`：已有主机的 `{id, version}`，正整数。
- `timeout_seconds`：流程整体时限，10–1800 秒，默认 900 秒，从执行器实际开始处理流程时计时。
- `steps`：1–20 个步骤。每步含 `name`、`command`、`success_exit_codes`、`timeout_seconds`。

步骤名称去除首尾空白后为 1–100 字符；完整命令为非空且不含 NUL 的最多 8192 字符文本；预期退出码为 1–16 个不重复的 0–255 严格整数，默认 `[0]`；步骤时限为 1–600 秒，默认 30 秒。实际返回的有效退出码保留原值，允许集合以外的码判定为失败。

流程详情在摘要基础上返回整体时限、当前事件序号和有序步骤。步骤详情包含编号、位置、名称、命令、预期退出码、时限、状态、可空退出码、可空停止原因、起止时间和 stdout/stderr。时间统一使用 UTC。摘要只包含识别目标、流程状态、步骤数和时间所需的字段，不返回命令大明细及输出。

## 提交幂等与记录删除

同一个 UUID 和同一规范化正文只会调度一次；再次提交返回原任务。正文不同而复用 UUID 返回 409。前端在请求结果不确定时保留原正文与 UUID，只有用户显式操作才重提；修改为新请求必须再次确认可能重复执行的影响。

删除记录后保留仅含 UUID 的已用提交标识，原 ID 再提交返回 409，防止迟到请求重新执行。该标识不保留命令、输出、主机和凭据。已用标识不自动清理；业务记录和输出保留至用户显式删除。

## SSE

先读取详情取得 `sequence`，再订阅 `events?after=sequence`。状态与事件在同一事务提交，序号按流程严格递增，每批最多读取 100 个事件。超前游标在建流前返回 422；不存在的任务返回 404。

| 事件 | 内容 |
| --- | --- |
| `state` | `{sequence, execution, steps}`；execution 包含流程状态字段，steps 包含全部步骤的状态字段 |
| `output` | `{sequence, step_id, stream, text}`；stream 为 stdout 或 stderr |
| `done` | `{sequence, execution}`；仅在流程终态且已发送完其事件后产生 |
| `error` | 空对象；当前事件流无法继续，不能据此认定远端操作未发生 |

步骤结束不会关闭整个流；无 `done` 的 EOF 不算完整接收。空闲期间每 10 秒发送 SSE 注释心跳。慢订阅与页面断线不阻塞或取消后台任务；所有输出先在服务端有界保存，客户端按照序号消费，并按总容量限制渲染。

## 资源、安全与生命周期

- 沿用当前单进程运行方式，4 个工作线程、最多 16 个活跃或排队流程，同一主机最多一个流程；最多 32 个 SSE 订阅。未提供多 worker/多实例协调。
- 单步骤 stdout 与 stderr 合计最多 256 KiB；过滤后的持久文本同样有该上限，最多 20 步。超限停止采集并记录 `output_limit`，不会默默丢掉输出后继续执行。
- UTF-8 采用跨块增量解码，非法字节替换为替代字符；应用日志不记录命令、输出或原始异常。已知目标及跳板密码、私钥会跨块过滤，包含已知资产凭据的命令拒绝创建。输出按不可信纯文本展示。
- 创建时、开始连接前和步骤执行前复核资产、凭据版本与服务器信任；继续使用严格公钥校验、资产凭据解析和连接清理，不接收临时密码或私钥。
- 应用关闭停止接收任务并取消本地命令采集；重启后不自动恢复或重新执行，遗留运行流程标为 `unknown`，未开始流程标为失败，剩余步骤跳过。持久化故障停止后续调度和相关 API，避免展示陈旧状态为有效结果。
- 此入口沿用当前受控控制台访问边界。项目尚无用户权限/多租户及操作者审计体系，SSH 公钥确认只验证服务器身份，本功能不宣称提供这些能力。

数据库仅新增 `ssh_executions`、`ssh_execution_steps`、`ssh_execution_events` 和 `ssh_execution_requests`，重复启动幂等创建并补齐已用标识；不修改或清除旧业务数据。输出仅保存在事件中，详情从事件合并，避免重复维护日志副本。

## 本次验证

本地回归使用隔离 SQLite、假资产和模拟 SSH，覆盖顺序与允许退出码、失败和未知结果停止、超时保留退出码、输出与 UTF-8、已知凭据过滤、幂等、删除后迟到提交、版本变更、事件与详情一致性、订阅释放、关闭与重启以及存储故障。实际通过 110 项：SSH 命令执行 21 项、新流程及连接状态 53 项、SSH 传输 23 项、按影响范围选取的巡检回归 13 项。传输测试另有 1 项因 Ed25519 没有传统 PEM 表示而跳过；巡检文件剩余 96 项未选择。一次较大的组合运行达到 60 秒时限后终止，随后拆分完成上述检查，不将被终止的运行计为通过。测试脚本按项目政策仅本地保存，不随 Git 交付。

前端 `npm run build`（包含类型检查）通过；本机 Edge 独立临时 profile、1440×900 视口及完全合成 API 验证了主导航、分页、创建与步骤排序、SSE 状态与输出、失败原因、纯文本安全、滚动和弹窗可达，无运行时或控制台错误。独立审核发现的超时误判、删除后重复派发和停止原因展示问题已修复并复核。未连接真实 SSH 主机；首次 POST 网络失败后的浏览器手动重提及真实网络断连未做完整端到端验证，不能把模拟验证视为生产验证。
