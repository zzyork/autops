# 跳板机管理

跳板机在资产管理下使用独立页面 `/assets/jump-hosts`，维护名称、IP 或域名、用户名、端口、密码或密钥路径以及备注。主机表单通过可清空的选择框关联跳板机，同一跳板机可被多个主机使用；修改跳板机配置对其关联主机统一生效。主机地址仍须为合法 IPv4 或 IPv6。

列表支持名称与地址搜索，并显示关联主机数量。被主机引用时禁止删除，须先解除关联。解除关联只修改主机引用，不删除独立跳板机及其凭据。

密码加密保存，接口不返回密码或密文。编辑时连接信息不变可留空保留密码；修改地址、用户名或端口须重新填写密码，切换为密钥认证会清除密码。密钥路径指后端机器上的路径，当前不连接服务器或检查文件是否存在。主机和跳板机更新均使用版本检查，过期表单返回 `409`。

## 接口

`/api/v1/jump-hosts` 提供列表查询和创建，`/api/v1/jump-hosts/{id}` 提供详情、更新和删除。列表接受可选 `q` 参数。更新需携带详情中的 `version`。响应包含 `host_count` 和 `has_password`，不存在的记录返回 `404`，关联删除或版本冲突返回 `409`，非法字段或缺少必要凭据返回 `422`。

主机接口 `/api/v1/hosts` 通过可空的 `jump_host_id` 保存关联，原 `proxy_*` 请求与响应字段已移除；旧接口调用方需同步调整。

## 旧数据库迁移

升级后首次启动自动将每台主机的旧跳板机配置迁入独立记录，名称沿用主机名称，保留连接信息、加密凭据并回填关联。不同主机的旧配置分别迁入，不自动合并。可在跳板机页面重新命名。

迁移前校验现有密钥和凭据；密钥丢失或不匹配会阻止启动。新增关联列和数据搬迁使用同一 SQLite 事务，失败回滚；成功后清空旧 `proxy_*` 字段，旧列保留但不再供模型或接口使用。重复启动不会重复导入，解除关联并删除后也不会从旧字段恢复。

升级前停止后端并同时备份数据库与对应密钥。启动和配置方法见仓库 README。
