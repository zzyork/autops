# AI 测试与交付规范

## 一、原则与验证责任

质量结论必须有实际证据。禁止将“文件已写入”“构建通过”“技能已存在”或模型自评等同于业务正确、客户端成功加载、人工审核通过或生产可用。

实施者必须选择与变更风险对应的检查，记录命令、环境、范围与结果；审核者核对证据和未覆盖路径；项目负责人决定新工具、例外及发布条件。无法自动判断的事项必须说明人工检查步骤和结果，禁止仅靠提示词声称强制执行。

## 二、现有检查基线

核实日期：2026-10-19。下表命令均从仓库配置推导，必须在仓库根目录执行并确认本地依赖；“配置已核实”不代表在本次任务中已执行。

| 检查 | 真实命令或位置 | 前置条件与当前状态 |
| --- | --- | --- |
| 前端类型 | `npm --prefix frontend run typecheck` | 来自 `frontend/package.json`，依赖已安装时可执行 |
| 前端构建 | `npm --prefix frontend run build` | 同一配置，包含类型检查及 Vite 构建 |
| 后端测试 | `.\.venv\Scripts\python.exe -m pytest` | Windows 根目录虚拟环境；pytest 配置指向 `backend/tests`，必须先确认本地测试存在 |
| 针对性后端验证 | 使用同一 Python 执行 `-m pytest`，后接已确认存在的本地测试路径 | 禁止猜测文件名、测试数量或用空收集声称通过 |
| 工作区与差异 | `git status --short`、`git diff`、`git diff --check` | 审核修改范围与空白错误，不能替代功能检查 |
| 代码规范/格式化 | 尚未配置项目级检查命令 | 禁止臆造 `lint`、Ruff、ESLint 或 Prettier 命令 |
| 前端自动测试、覆盖率和性能门槛 | 尚未配置统一工具与阈值 | 根据实际风险记录验证方式；新工具先按依赖准入处理 |
| CI、依赖漏洞/许可证/秘密扫描与 OpenAPI 自动校验 | 仓库尚未配置流水线及门禁 | 只能标记为未配置，禁止报告为已通过 |

其他平台使用该环境已确认的 Python 可执行文件，禁止照搬 Windows 路径。依赖与脚本变化时同步核查本表，不自动安装新检查工具。

所有正式回归测试、临时测试和验证脚本均仅用于本地验证，禁止暂存或提交到 Git，也禁止通过忽略例外或强制添加绕过规定。克隆仓库不保证具备本地测试；执行前必须核查，缺失时明确报告，不能因此声称后端测试已通过。测试政策不构成删除失败测试、弱化断言或跳过应做验证的理由。

## 三、按变更类型验证

| 变更类型 | 必须执行的适用检查与证据 |
| --- | --- |
| 纯文档、规范或文案 | 实际内容、路径/引用、命令来源、Markdown 结构和最终差异；不要求运行与改动无关的应用测试 |
| 前端代码 | 既有类型检查与构建；覆盖受影响的加载、成功、无数据、失败、保存和长内容状态 |
| 界面或用户流程 | 在具备浏览器条件时验证 1440px 桌面布局、键盘操作、焦点、危险操作及取消/失败；条件不具备时列明未执行项，禁止声称已完成视觉验收 |
| 业务逻辑或缺陷修复 | 正常、异常、边界和回归场景；用本地测试或可重复的人工步骤验证外部可观察行为 |
| API、SSE 或下载 | 输入输出、状态码、字段过滤、真实事件/内容、异常、取消和消费者兼容性 |
| 数据模型、事务或迁移 | 旧数据、升级顺序、事务回滚、并发不变量及恢复；不可逆操作先确认并验证恢复方案 |
| 权限、安全、文件或敏感数据 | 允许与拒绝路径、越权、异常输入、超限、秘密及日志泄露检查 |
| 依赖、启动或部署配置 | 版本兼容、配置、构建/启动、健康检查、生命周期和受影响恢复步骤 |
| 跨模块或重大重构 | 在上述检查之外扩大到相关公开接口和关键流程，不以无关测试替代覆盖 |

未配置自动工具时必须明确缺口与替代验证的覆盖限制；如果无法验证且继续实施可能造成实质风险，暂停依赖该结果的步骤并报告阻塞。

## 四、测试设计与失败处理

- 测试必须验证可观察行为、业务不变量或稳定契约，禁止只复制实现或为低风险可逆改动堆叠无价值测试。
- 对可自动复现且存在回归风险的缺陷，必须补充本地回归测试；无法自动复现时，记录原因、人工复现和修复验证结果。
- 测试必须能独立执行，使用隔离数据并清理自身数据；网络、时间和随机性使用受控来源，禁止依赖其他测试顺序或生产资源。
- 必须检查失败和边界，不只验证成功。并发、重复投递、取消、超时、流中断和资源释放按本次数据流选取。
- 检查失败时读取完整错误，区分本次改动、既有问题和环境原因；修复后执行对应检查。只有新变化、失败或未消除风险才继续扩大或重复验证。
- 禁止删除失败用例、放宽断言、关闭类型/安全检查、降低门槛、吞掉异常或用 `|| true` 等方式制造通过。

检查缺失、跳过、失败和无法执行必须分别记录，禁止将缺失必需脚本当成成功。将来配置 CI 时，必需检查缺失必须明确失败或进入有批准记录的初始化/例外状态，禁止静默跳过。

## 五、审核与完成定义

按实际变更选择审核范围，使用三份核心规范及相关专项清单：

- 目标与验收对应，修改只服务当前任务，无意外删改、全仓格式化或无关重构。
- 模块职责、依赖方向、同一业务规则的复用、共享组件及接口消费者已检查。
- 前端按现有桌面标准、状态、统一错误入口、分页和可访问性验收；禁止通用检查引入移动端要求。
- 后端按输入输出、事务、并发、幂等、任务状态和资源清理验收，保留最小必要响应与业务证据。
- 敏感输入、文件、URL、凭据、日志及权限边界已按风险检查。
- 兼容、迁移、恢复及文档引用与最终实现一致；验证结果和未验证项可追溯。
- 最终差异无秘密、测试文件、运行数据或生成产物被误纳入交付；人工审核仍按项目工作约定执行。

| 交付状态 | 判定 |
| --- | --- |
| 完成 | 适用验收及本次必需验证已满足，证据可核查；不代表提交、人工批准或上线 |
| 部分完成 | 有可交付结果，但存在明确未完成的必需项 |
| 阻塞 | 缺少继续实施所需的决策、权限、依赖或环境 |
| 未验证 | 已修改，但关键验证未执行或结果不确定 |

交付必须说明完成内容、主要文件、实际检查及结果、未执行项及原因、兼容风险和后续事项。项目本就未配置、且本次任务不要求新增的工具，列为现状或后续条件；禁止用“不适用”掩盖本次应做但未做的验证。

## 六、Git 与协作

修改前后必须检查工作区及差异，保留用户未提交内容；只暂存当前任务文件。提交、推送、创建合并请求、修改分支保护或发布均须有对应授权，规范模板和示例命令不提供授权。

获准提交时，必须检查 `git status`、`git diff`、`git log --oneline -10`，沿用仓库提交风格。暂存前后核对跟踪清单与暂存区，禁止包含测试、秘密、运行数据、依赖和构建产物。发现已跟踪测试时按 `AGENTS.md` 取消跟踪并保留本地文件；禁止删除测试内容来规避检查。

禁止未经明确授权执行硬重置、强制推送、改写共享历史、清理他人工作或删除远程分支。禁止为满足提交格式而改写无关历史。

每个提交聚焦一个目标。合并请求使用 [统一模板](templates/合并请求模板.md)，说明问题与最终行为、验证、兼容/数据影响及适用的界面证据。仓库托管平台、分支策略和保护规则须核实或由负责人决定；禁止从模板推定已配置 GitHub 或必需 CI。

## 七、配置、部署与恢复

当前仓库提供本地开发启动和健康接口，尚未建立生产部署流水线。项目仍只有单 worker、无多人认证；本规范不将其改写为已具备生产访问控制或多实例协调。

修改运行环境或准备发布时必须逐项确认：

1. 实际开发、测试、预发布和生产环境；不存在的环境明确记录，禁止臆造。
2. 配置项名称、用途、默认行为、敏感性和环境归属；示例仅使用虚构值。禁止复制生产凭据到测试或将调试、默认账号和宽松访问策略带入生产。
3. 依赖版本、可重复构建、源码与产物对应关系、部署前检查、迁移顺序和健康验证。
4. 适用的存活/就绪、日志脱敏、关联标识、业务/错误/延迟/资源指标、告警、故障处理和保留期限；不适用项说明依据，未配置项明确列出。
5. 回滚触发条件、应用与数据库兼容、前向修复、负责人和恢复验证；不可逆变化必须提前说明并取得明确授权。

现有 `/health`、`/api/v1/health` 可用于对应健康响应验证，但不能据此宣称全部数据库、SSH、模型和后台任务均已就绪。

默认运行数据位于 `backend/runtime/`。沿用 README 的停服备份方式，保存完整实际数据目录；配置改过数据目录时按真实位置备份。必须同时保护数据库、凭据加密密钥及其他运行数据，禁止仅备份数据库后声称可恢复。

备份频率、保留期限、位置、权限、加密和恢复演练周期必须由负责人明确；本次未定义或执行。恢复验证必须在隔离环境记录结果与耗时，备份文件存在或备份任务成功不能证明恢复成功。禁止未经授权删除备份、覆盖恢复点或缩短保留期。

包含凭据、加密密钥、个人数据或其他敏感业务信息的备份必须加密存储，按最小权限控制访问并记录访问情况；具体加密、访问记录和恢复方案由负责人确定并验证，禁止将策略未确定视为允许明文保存。

生产部署、生产数据写入、网络/密钥变更、真实费用和外部系统副作用按 `AGENTS.md` 取得明确授权；已授权的准备工作、配置审核和可逆修复继续执行，禁止将文档清单变为重复审批流程。
