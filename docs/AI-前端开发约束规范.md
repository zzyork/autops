# AI 前端开发约束规范

## 一、范围与开发前检查

本规范适用于页面、组件、路由、状态、类型、样式、请求和浏览器交互。具体框架、组件库、设备范围和错误反馈由 [项目配置](../项目配置.md) 核实，禁止把其他项目或示例技术栈作为默认要求。采用相应技术栈时才执行已启用的 [Vue 专项](../profiles/Vue3前端技术栈规范.md)；[UI 规范样板](../profiles/UI规范样板.md) 仅在项目明确选择适用方案时执行。

前端任务必须自动使用 `frontend-design` 和 `ui-ux-pro-max`，按[技能优先与规范补充](AI-编程接入指南.md#技能优先与规范补充)判断适用要求：技能已具体覆盖的采用技能，不再叠加本文同类条款；本文只补充未覆盖的要求。完整阅读用于识别缺口，不代表所有条款与技能重复执行。项目已批准的需求、基线和契约继续作为约束。

修改前必须从项目索引定位并阅读实际页面、组件、API、类型、路由和样式，理解数据流、状态归属、错误与权限边界，搜索共用实现及调用方。先说明目标、文件、用户可见变化、风险和验证，再小步修改；禁止直接生成整页或擅自换架构、依赖、主题及设计系统。

## 二、职责、复用与文件组织

- 页面组织业务流程；表格、搜索、表单及独立业务细节按职责组织。禁止将多个独立功能、权限、编辑、导出与全部数据处理堆入巨型页面。
- 同一业务规则出现两次必须评估并抽取共用实现；仅外观相似、语义或变化独立时禁止强行合并。优先已有组件、组合逻辑、API、工具、类型和布局。
- 新建组件在实施说明中交代用途、输入、输出、事件/副作用、依赖及复用范围，不要求重复添加源码注释。修改共用组件必须核对全部已知消费者和默认行为。
- 文件按职责、可理解性和变更边界组织；目标项目已批准行数门槛时按其配置执行，通用规范不设置统一行数阈值。职责混杂时评估拆分，禁止为行数机械切割。目录、命名及独立页面/路由沿用目标项目的已批准结构。
- 业务状态与协议值使用具名常量或明确类型；注释说明设计、业务和兼容原因，禁止无关优化和重复解释代码。
- 源码排版必须执行[源码排版与可读性](AI-奥卡姆剃刀开发规范.md#源码排版与可读性)：样式规则展开、每条属性声明独占一行，模板与脚本按逻辑层级换行和缩进，禁止将样式块、模板或多条语句压成一行。

## 三、类型与数据边界

TypeScript 项目禁止 `any`，外部未知数据使用 `unknown` 并在边界收窄或校验。对象、请求响应、组件输入输出和业务状态使用明确类型，禁止以空对象扩散隐式类型。

禁止用双重断言、无依据的非空断言、`@ts-ignore` 或放宽严格配置掩盖契约问题。空值、缺省、枚举、日期、单位和数值精度必须与服务端一致，静态类型不能代替运行时验证。其他语言采用目标项目已批准的类型与校验机制。

## 四、状态、副作用与生命周期

局部弹窗、表单、加载和页面交互状态归最近的组件或模块；只将确有跨页面共享需要的信息、权限和全局配置放入已批准的共享机制。禁止为局部状态自行新增全局 Store 或安装状态库。

派生值优先从权威状态计算，不维护无用途的重复副本。计算与模板表达式不能隐藏请求、状态写入或其他无关副作用。订阅、侦听、计时器、监听器、轮询和请求必须明确取消、清理或结果失效边界，覆盖参数切换、卸载、隐藏和竞态中适用场景。

禁止添加无需求依据的自动刷新、轮询、动画、重复网络请求或后台页面副作用；任务与状态必须具有生命周期和消费者。

## 五、请求与错误处理

页面和业务组件必须使用既有 API 层及统一请求客户端，禁止直接散落 `fetch`、`axios` 调用或重复拼接地址、认证头和通用错误。路径从项目配置及实际源码确认，不默认存在任何示例文件。

请求失败必须终止当前操作、恢复加载/保存状态、保留未保存表单，禁止提示成功、关闭未保存表单或继续依赖成功结果的步骤。失败、正常空数据、取消、未完成和结果未知分别表达。过期请求不能改写状态或弹出错误。

写入请求超时、断连或取消不证明服务端未执行或已回滚；界面不能据此恢复旧业务结果并声称未发生。结果未知时按既有契约查询或等待确认，禁止擅自重复提交、补偿或新增轮询机制。

本地字段校验可以给出具体原因，已定义的业务状态按契约处理；请求错误展示由项目已批准的政策集中维护，禁止页面各自硬编码通用文案、展示敏感内部详情或自行推测原因。只有项目明确采用固定“系统异常”政策时，才同时执行其统一文案、禁止改写详情和禁止按状态码提供建议等约束。

业务失败状态使用布尔值、枚举等明确标识，禁止通过文案赋值或相等比较判断。列表、详情、保存、删除分别管理状态；保存失败不等于列表加载失败。错误消息消失不表示成功，失败时禁止渲染正常空态或使用备用数据。

新增默认值、降级、备用源、自动重试或其他兜底前，必须说明触发条件、行为、影响并按已有授权确认；禁止以通用规范授权新的错误机制。

## 六、界面、信息与可访问性

先确定结构和数据流，再划分组件与复用点，最后按已有设计标准实施。颜色、间距、字体、控件、主题及设备范围沿用已批准约定，禁止因通用响应式检查自行增加移动端，也禁止把桌面限制强加给已有移动业务。

需要选择组件尺寸、内外间距、排版或状态样式时，先采用两项技能的适用资料；已覆盖的事项不再套用[前端样式推荐表](前端样式推荐表.md)。仅对技能缺口可以查表补充，选定后记录实际值、变量和依据；已启用 UI 规范时引用其记录，不覆盖项目已批准基线。

所有标题、字段、统计、提示、tooltip 和操作必须有明确用户用途；禁止因 API 返回就全量展示对象、内部配置、调试流程或无用途元数据。保留核心结果、影响、必要状态和危险操作确认；低频但有效的证据和明细可以展开，无用途内容删除而非藏入折叠区。

展开控件必须在默认状态可识别，使用按钮语义、清晰动作与对象、键盘切换及同步的展开状态；需要关联内容时使用唯一 ID，隐藏内容退出 Tab 顺序。禁止把核心结果藏入折叠区或以页面链接冒充展开按钮。

表单具有标签、校验、保存中状态和重复提交保护；删除、覆盖或批量不可轻易撤销操作说明对象和影响并要求明确确认。异步界面覆盖加载、成功、无数据、失败和禁用等适用状态。

交互支持键盘并有可见焦点，图标按钮和输入具备可访问名称，状态不只靠颜色区分；普通文字对比度至少 4.5:1，控件边界和焦点与相邻背景至少 3:1。长名称、表格和弹窗保留完整信息与操作可达性。

列表与资源加载必须有明确规模上限，分页、分段或虚拟加载采用已批准方案，数据和总数来自真实结果。启用 UI 规范模板时，按其已批准组件条目执行，页长选项、页面结构和验收视口由项目确认，不因启用模板自动采用示例值。

## 七、安全、审核与交付

禁止将秘密放入前端源码、环境变量或构建产物；禁止敏感日志、`eval()` 执行不可信输入或直接插入未处理 HTML。动态 HTML、Markdown、文件与下载按上下文校验/转义，前端校验不能代替服务端授权。

保留已有权限、凭据处理、冲突及危险操作语义。架构调整、核心设计变更或大规模重构先分析并按授权确认，禁止仅为“优化”整体重写。

前端改动仅进行打包测试，命令、通过依据及另行授权边界按[测试与交付规范](AI-测试与交付规范.md#三按变更类型验证)执行，禁止自动追加独立类型检查、业务或浏览器测试；打包命令内置的必要检查按该规范处理。未配置、未执行和未覆盖项如实说明。源码与差异审核至少确认复用、类型、状态、请求层次、生命周期、界面范围、信息必要性、可访问性、输入安全和调用方兼容。代码仍须人工审核，提交和合并按授权执行。
