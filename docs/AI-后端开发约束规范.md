# AI 后端开发约束规范

## 文档目的

本规范用于约束 AI 辅助后端开发行为，确保生成代码符合项目架构、安全要求、接口规范和长期维护要求。

适用于本项目所有后端接口、服务、数据库访问、任务处理、配置管理和测试代码。

## 一、基本原则

### 1.1 修改前理解项目

AI 修改前必须：

1. 阅读项目索引和相关源码。
2. 理解现有接口层、业务层、数据层职责。
3. 查找已有模型、工具函数、异常处理方式。
4. 优先复用已有实现。

禁止看到需求后直接创建重复接口或重复服务。

## 二、架构约束

后端代码按职责拆分：

- 路由层：处理 HTTP 输入输出。
- Schema/DTO 层：定义请求和响应结构。
- Service 层：处理业务逻辑。
- Repository/DAO 层：处理数据访问。
- Utils 层：处理无业务关联公共能力。

禁止将全部逻辑集中在接口文件中。

## 三、API 开发规范

- 接口必须具有明确请求和响应模型。
- 不返回内部异常堆栈。
- HTTP 状态码必须表达真实结果。
- 接口字段必须有明确类型。
- 修改接口时同步检查调用方。

FastAPI 项目：

- 使用 Pydantic 模型校验输入输出。
- 使用依赖注入复用认证、数据库连接和公共逻辑。
- 根据实际 I/O 类型选择 async 或 sync。

## 四、数据库规范

- 禁止在接口层直接编写复杂 SQL。
- 数据库访问集中管理。
- 修改表结构必须同步迁移文件。
- 查询必须明确字段，避免无意义的大范围查询。
- 防止 SQL 注入，使用参数化查询。

## 五、异常处理

禁止：

- 捕获异常后静默忽略。
- 返回虚假成功结果。
- 使用默认数据隐藏失败。

要求：

- 区分业务异常和系统异常。
- 日志记录必要上下文。
- 对外隐藏敏感内部信息。

## 六、安全规范

AI 必须遵守：

- 所有外部输入均视为不可信数据。
- 服务端必须执行校验。
- 限制输入长度、类型和值范围。
- 防止 SQL 注入、命令注入、路径穿越。
- 不记录密码、Token、密钥等敏感信息。
- 文件上传必须校验类型和大小。

## 七、配置与依赖

- 敏感配置使用环境变量或安全配置中心。
- 新增依赖必须说明用途。
- 固定版本方式遵循项目已有规则。

## 八、测试要求

修改接口或核心逻辑后：

- 验证正常流程。
- 验证异常流程。
- 验证权限和边界条件。

不要编写只重复实现代码的无价值测试。

## 九、AI 修改流程

需求分析 → 阅读代码 → 制定方案 → 修改 → 验证 → 汇报。

涉及架构调整、大规模重构、数据迁移时必须先确认。

## 十、审核清单

- [ ] 是否复用已有能力。
- [ ] 是否保持架构职责。
- [ ] 是否有明确类型。
- [ ] 是否正确处理异常。
- [ ] 是否存在安全风险。
- [ ] 是否完成必要验证。
