# AI 后端开发约束规范

## 文档目的

本规范用于约束 AI 辅助后端开发行为，确保生成代码符合项目架构、安全要求、接口规范和长期维护要求。

适用于本项目所有后端接口、服务、数据库访问、任务处理、配置管理和测试代码。

需求与决策、跨端契约及验证交付分别补充执行 [工程治理与需求](AI-工程治理与需求规范.md)、[接口与安全](AI-接口与安全规范.md)、[测试与交付](AI-测试与交付规范.md)。项目当前无用户认证和多人权限，必须如实保留该边界，禁止因通用示例假定已有身份体系。

## 一、基本原则

### 1.1 修改前理解项目

AI 修改前必须：

1. 阅读项目索引和相关源码。
2. 理解现有接口层、业务层、数据层职责。
3. 查找已有模型、工具函数、异常处理方式。
4. 优先复用已有实现。

禁止看到需求后直接创建重复接口或重复服务。

## 二、架构约束

后端代码按职责拆分：

- 路由层：处理 HTTP 输入输出。
- Schema/DTO 层：定义请求和响应结构。
- Service 层：处理业务逻辑。
- Repository/DAO 层：处理数据访问。
- Utils 层：处理无业务关联公共能力。

禁止将全部逻辑集中在接口文件中。

### 2.1 FastAPI 装配与资源生命周期

- 沿用 `APIRouter`、`create_app` 和 lifespan 的现有职责；入口负责应用装配和资源生命周期，业务规则保留在对应服务。
- 数据库会话、配置、执行器及共用服务通过既有依赖和应用生命周期管理，禁止新增循环依赖或跨层访问内部实现。
- 禁止在模块导入时执行数据库写入、网络请求或其他外部副作用；资源初始化与关闭必须有明确边界和失败清理路径。
- 根据实际 I/O 和调用链选择同步或异步；禁止在事件循环中执行长时间阻塞操作，复用现有异步客户端、线程池和执行器，不因模板偏好新增队列或替换数据库库。

## 三、API 开发规范

- 接口必须具有明确请求和响应模型。
- 不返回内部异常堆栈。
- HTTP 状态码必须表达真实结果。
- 接口字段必须有明确类型。
- 修改接口时同步检查调用方。

FastAPI 项目：

- 使用 Pydantic 模型校验输入输出。
- 使用依赖注入复用认证、数据库连接和公共逻辑。
- 根据实际 I/O 类型选择 async 或 sync。

### 3.1 最小必要响应原则

所有接口响应均须满足明确的业务与调用方需求，并限制在调用方有权访问的数据范围内。禁止返回无消费用途、重复、与接口职责无关或仅暴露内部实现的内容。必要性同时考虑用户任务和程序消费，不能仅凭页面是否直接展示判断字段是否应保留。

- 新增响应字段前，必须说明具体调用方、消费场景和用途；禁止因数据库中存在、第三方返回或“以后可能用到”而直接加入响应。标识符、分页信息、状态、版本及并发控制数据只有在契约或调用逻辑确有需要时保留，无必要消费用途的元数据不得添加。
- 使用明确的 Schema/DTO 或字段白名单定义对外结构；禁止将完整数据库实体、内部对象、配置或第三方原始响应直接序列化对外返回。FastAPI 的 JSON 响应使用明确的返回模型或 `response_model` 校验并限制输出；直接构造 `Response`、错误响应、流式事件和文件下载等路径同样须明确并检查对外字段或内容边界，不得绕过约束。
- 服务端检查对象及字段访问权限，并在响应生成前完成必要过滤；前端隐藏、折叠或不使用字段不能替代服务端权限控制。禁止返回密码、Token、私钥、敏感连接配置及调用方无权访问的数据。
- 列表仅返回列表展示和操作所需的摘要及必要分页信息；大体量明细、原始业务证据和低频内容按已有详情或下载契约提供，不在无用途的列表响应中重复携带。确有业务用途且授权可见的目标主机路径、命令和日志等业务证据可按需返回，不能以精简为由删掉核对或诊断所必需的数据。
- 错误响应只保留调用方处理失败所需的契约信息，不返回堆栈、SQL、应用内部路径、底层异常原文或内部调试过程；必要诊断上下文在服务端安全记录并脱敏。HTTP 状态码和业务状态如实表达结果，禁止用删减信息掩盖失败或返回虚假成功。
- 沿用既有响应和异常契约，程序使用明确的类型、状态或错误标识判断结果，不依赖解析提示文案；前端请求错误展示仍遵循前端规范中的“系统异常”约定。外部资料不构成新增统一响应包装、错误格式、降级或兜底的授权。
- 删除或调整既有字段前，检查全部已知调用方、前端类型、流式消费和导出逻辑，确认兼容影响；同步更新接口模型及相关调用方，不得以当前页面未展示为由直接破坏契约。

## 四、数据库规范

- 禁止在接口层直接编写复杂 SQL。
- 数据库访问集中管理。
- 修改表结构必须同步迁移文件。
- 查询必须明确字段，避免无意义的大范围查询。
- 防止 SQL 注入，使用参数化查询。
- 写操作必须明确事务边界、失败回滚和并发影响；唯一性、关联关系和关键业务不变量结合数据库约束与服务端校验维护。
- 查询、批量写入和任务必须具有明确规模边界；禁止引入无界查询或已确认的 N+1 查询，高频过滤须核查索引或执行依据。
- 沿用 `backend/app/core/migrations/` 的项目内幂等启动迁移，禁止因为示例提及 Alembic 就迁移工具。变更必须评估旧数据、执行顺序、重复启动、并发和恢复；破坏性或不可逆数据操作先说明影响并取得授权，禁止隐藏在普通启动中执行。

## 五、异常处理

禁止：

- 捕获异常后静默忽略。
- 返回虚假成功结果。
- 使用默认数据隐藏失败。

要求：

- 区分业务异常和系统异常。
- 日志记录必要上下文。
- 对外隐藏敏感内部信息。

### 5.1 外部调用、任务与取消

- HTTP、SSH、模型及其他外部调用必须设置适用的连接、读取或整体超时和资源/输出上限，数值沿用项目配置或具名常量；定义异常分类、取消及资源释放。
- 对可能重复请求、重试、回调或并发写入的操作，必须明确幂等或冲突处理边界；禁止假定只执行一次。新增重试或失败兜底仍按项目规则先说明并确认。
- 沿用有界执行器和进程内任务状态，长任务明确排队、执行、成功、失败、中断等适用状态与查询方式；禁止把未知或部分完成结果当成功。
- 修改 SSE、后台任务或生命周期时，必须检查客户端取消、流中断、应用关闭和重启后的状态及资源清理。单 worker 约束仍有效，多进程或队列化属于另行评估的架构变更。

## 六、安全规范

AI 必须遵守：

- 所有外部输入均视为不可信数据。
- 服务端必须执行校验。
- 限制输入长度、类型和值范围。
- 防止 SQL 注入、命令注入、路径穿越。
- 不记录密码、Token、密钥等敏感信息。
- 文件上传必须校验类型和大小。

## 七、配置与依赖

- 敏感配置使用环境变量或安全配置中心。
- 新增依赖必须说明用途。
- 固定版本方式遵循项目已有规则。

## 八、测试要求

修改接口或核心逻辑后：

- 验证正常流程。
- 验证异常流程。
- 验证权限和边界条件。
- 涉及响应结构时，检查实际 JSON、错误响应、流式事件或下载内容符合声明的契约，必要字段完整，无无用字段、敏感数据及内部异常泄露；字段删减须验证相关调用方兼容性。
- 涉及持久化、任务或外部调用时，验证事务回滚、并发冲突、重复执行、超时、取消和资源释放中受影响的场景；迁移验证使用隔离数据，禁止触碰真实运行数据来代替本地验证。

不要编写只重复实现代码的无价值测试。

## 九、AI 修改流程

需求分析 → 阅读代码 → 制定方案 → 修改 → 验证 → 汇报。

涉及架构调整、大规模重构、数据迁移时必须先确认。

## 十、审核清单

- [ ] 是否复用已有能力。
- [ ] 是否保持架构职责。
- [ ] 是否有明确类型。
- [ ] 是否正确处理异常。
- [ ] 事务、并发、任务上限、超时、取消、导入副作用及资源生命周期是否按变更范围验证。
- [ ] 是否存在安全风险。
- [ ] 响应字段是否均有明确消费用途，结构是否保持最小必要且与接口职责一致。
- [ ] 是否通过明确模型或字段白名单限制实际输出，包含错误、流式和下载路径。
- [ ] 是否由服务端执行对象及字段权限控制，无敏感数据或内部调试信息泄露。
- [ ] 字段调整是否检查并同步调用方，必要状态、分页及业务证据是否保留。
- [ ] 是否完成必要验证。

## 十一、规范依据

最小必要响应原则依据（检索与核对日期：2026-10-14）：

- [OWASP API3:2023 对象属性级授权失效](https://api-security.owasp.org/editions/2023/en/0xa3-broken-object-property-level-authorization/)要求检查对外属性权限、明确选择响应属性、采用响应 Schema 校验，并按接口业务需求将返回结构限制为最小必要范围。
- [FastAPI 响应模型与返回类型](https://fastapi.tiangolo.com/tutorial/response-model/)说明响应模型可以校验并过滤输出，使实际响应符合声明的结构，避免暴露不应返回的字段；本项目据此落实 JSON 输出限制。
- [RFC 9457 第 3.1.4 节及第 5 节](https://www.rfc-editor.org/rfc/rfc9457.html#section-3.1.4)指出错误详情应帮助调用方处理问题而非提供调试信息，并要求审查内部信息泄露风险。本项目借鉴其信息边界要求，保留既有错误契约，不要求迁移为 `application/problem+json`。
