# AI 后端开发约束规范

## 一、范围与理解现状

适用于接口、业务、数据库、配置、外部调用、后台任务及后端验证。具体语言、框架、存储、认证、部署和迁移方式以 [项目配置](../项目配置.md) 及实际源码为准；禁止预设数据访问库、数据库、启动迁移、进程数或认证模式。FastAPI 仅在 [专项](../profiles/FastAPI技术栈规范.md) 明确启用且实际采用时适用。

修改前阅读索引、入口、路由、模型、服务、持久化、调用方及验证，理解输入、权限、数据、事务、输出和失败传播，查找复用能力。方案说明目标、文件、职责、契约、影响、风险及验证，禁止重复接口或未分析就生成完整实现。

## 二、职责、依赖与生命周期

按实际架构区分 HTTP 输入输出、请求响应模型、业务规则、数据访问和公共基础设施；既有项目沿用已批准层次。新项目先明确边界，不为模板机械新增 Repository 或直接跳过已有层次。禁止循环依赖、跨层访问内部实现及把全部规则堆在路由、启动入口或数据库实体中。

入口负责装配和资源生命周期，资源初始化、依赖作用域、失败清理及关闭责任必须明确；禁止在导入模块时执行写库、网络或其他外部副作用。

按实际调用链和 I/O 选择同步、异步或现有执行器，禁止在事件循环直接执行长时间阻塞工作，也禁止假定加 `async` 即自动非阻塞。不因框架示例新增队列、改库或改变进程模型。

## 三、接口与最小必要响应

接口必须有明确请求响应模型、字段类型、校验和真实 HTTP 状态码。修改接口同步核对全部已知消费者、前端类型、流式及导出，执行 [接口与安全规范](AI-接口与安全规范.md)。

- 每个字段说明调用方和用途；标识符、分页、状态、版本及并发信息按真实消费保留，禁止因数据库有字段或“以后可能用到”就暴露。
- 用明确模型或字段白名单过滤实际响应，禁止直接序列化完整数据库实体、配置或第三方对象；错误、直接响应、流式和下载不能绕过内容边界。
- 服务端执行适用的对象、字段和功能权限，禁止依赖前端隐藏。禁止返回密码、Token、私钥、无权数据及敏感连接配置。
- 列表以摘要和必要分页为主，大明细和低频原始证据按详情/下载契约提供；诊断必需且授权可见的目标路径、日志等属于业务证据，不能一概删去。
- 错误不返回堆栈、SQL、应用内部路径或底层异常原文；服务端仅安全记录必要脱敏上下文，禁止掩盖失败或虚假成功。
- 沿用已批准响应和异常形态，业务用类型、状态或稳定错误标识判断，禁止解析提示文案。字段删改前明确兼容和迁移，禁止因当前页面不展示而破坏程序消费。

## 四、数据、事务与迁移

数据访问按既有职责集中，复杂查询不堆在路由；查询明确目标字段与范围，使用参数化机制防注入。禁止接入无界查询、已确认的 N+1 或无批次上限的批量写入，高频查询核查索引或执行依据。

写入必须说明事务所有权、提交、失败回滚、唯一性、关系约束和并发不变量。同一记录可能并发改变时选择符合实际需求的冲突或并发控制并验证，禁止假定请求只执行一次。

结构变更同步已有迁移实现，评估旧数据、执行顺序、重复执行、并发写入和版本兼容。可逆迁移验证升级与回滚；不可逆迁移说明数据影响、备份、前向修复与恢复，按授权执行。禁止清库、删历史或将破坏性操作隐藏在普通启动中，也禁止为模板改换迁移工具。

## 五、异常、外部调用与任务

区分输入、认证/授权、资源缺失、冲突、依赖故障及系统错误，沿用异常转换契约。禁止空捕获、静默忽略、默认数据掩盖失败或无条件成功。日志包含可排障上下文，按权限和敏感边界脱敏。

外部服务、命令执行或其他 I/O 必须定义适用的连接/读取或整体时限、资源/输出上限、错误分类、取消和释放，数值来自配置或具名常量。重试说明条件、次数或总时限与幂等保障，非幂等副作用无去重保障时禁止自动重试；新增重试和兜底先按授权确认。

任务具有明确执行上限、状态、失败原因及消费者；长任务提供查询或约定的状态反馈。排队、运行、完成、失败、取消、中断及结果未知根据真实状态区分，不能把部分结果或流提前结束当成功。检查客户端断连、应用关闭和重启后的恢复/中断边界。

缓存、历史、重试、队列和分布式协调仅在已确认需求下增加，并说明一致性、生命周期和维护责任。进程数或协调模型来自实际部署，不从本包推定。

## 六、安全、配置与依赖

所有外部输入包括第三方响应都不可信，服务端执行类型、格式、长度、范围、枚举及业务关系校验；金额、精度、时区和状态转换有明确语义。文件/URL 功能验证上传、路径、解析、SSRF 与资源消耗边界。

认证和授权以实际访问模型为准；新增或改变身份、安全和密钥边界先取得授权，已有敏感操作不能仅靠隐藏按钮保护。秘密通过受控配置或安全存储管理，禁止写入源码、镜像、日志、测试或文档；不能因为模板只举环境变量就改写现有安全存储。

运行配置分环境控制，版本策略与依赖准入按 [工程治理与需求](AI-工程治理与需求规范.md)。禁止自行升级、更换主要库或关闭安全限制来使检查通过。

## 七、验证与审核

后端改动仅进行运行启动测试，命令、通过依据、资源清理及另行授权边界按[测试与交付规范](AI-测试与交付规范.md#三按变更类型验证)执行，禁止自动追加接口、业务、事务、并发或迁移测试。正常、异常、权限、边界、真实输出、消费者兼容、事务回滚、并发、迁移、重复执行、超时、取消和释放仍须进行源码与差异审核，未执行的运行验证必须如实说明。使用隔离环境，禁止生产写入替代本地验证。

审核必须核实复用、类型、分层、输入输出、安全、状态、生命周期和必要复杂度；启动通过不能证明业务行为与不变量正确。检查命令必须来自目标配置，未执行、未配置或失败分别说明，不能用规范文件代替证据。完成代码需人工审核，提交和发布遵循授权。
