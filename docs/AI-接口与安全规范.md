# AI 接口与安全规范

## 一、适用范围与现有边界

本规范用于 HTTP 接口、前后端契约、SSE、下载、外部输入、文件、敏感数据及安全配置，与前后端核心规范共同执行。具体请求封装、界面错误展示和最小必要响应分别以对应核心规范为准。

项目当前没有用户认证和多人权限，仅支持单 worker。这些是现有运行限制，不是已实现的安全控制，也不构成将服务公开给不可信用户的安全保证。新增认证、角色、租户、多人使用或改变访问边界前，必须明确方案、兼容影响和授权，禁止假定已有当前用户或权限体系。

## 二、接口契约的权威来源

JSON 接口以 FastAPI 路由声明和 Pydantic 请求/响应模型为实现来源，生成 OpenAPI；前端 `frontend/src/api/`、`frontend/src/types/` 及验证必须与实际契约一致。禁止单独维护与实现不一致的第二份字段定义，也禁止从通用示例推定现有错误结构。

OpenAPI 无法完整表达的 SSE 事件、取消行为和下载内容，必须在任务契约中补充，并核对实际生产方与消费方。新增工具或采用其他 OpenAPI 版本前，必须核实当前 FastAPI 与消费工具的支持范围。

每个新增或修改的接口必须明确以下适用项目，不适用项说明原因：

| 项目 | 必须定义的内容 |
| --- | --- |
| 操作 | 用途、方法、路径、版本及唯一操作标识 |
| 输入 | 路径、查询、请求头、请求体；字段类型、必填性、可空/缺省语义、默认值和限制 |
| 结果 | 实际成功状态码、响应模型、失败状态和稳定业务状态；禁止依赖解析提示文案 |
| 访问 | 运行边界、敏感字段及适用的对象/字段/功能权限 |
| 集合 | 分页、页长上限、排序稳定性、筛选和总数语义 |
| 副作用 | 事务、重复请求、幂等性、并发、取消及结果未知时的行为 |
| 兼容 | 消费者、弃用/替代条件、数据迁移影响及脱敏示例 |

日期、时区、金额、精度、单位、枚举和状态转换必须有明确语义；禁止前后端各自猜测或以类型断言掩盖不一致。

## 三、响应、错误与兼容性

- 必须执行后端规范中的最小必要响应原则，用模型或字段白名单限制 JSON、错误、流式和下载内容。标识符、版本、分页及业务证据的必要性同时考虑程序消费。
- HTTP 状态码必须如实表达结果；空列表、缺失资源、可空字段和缺省字段分别定义，禁止把错误一律转换为 HTTP 200 或成功空数据。
- 沿用既有响应及异常约定，禁止因为外部示例包含 `error`、`code`、`request_id` 就新增统一包装或强制所有响应增加字段。
- 错误响应禁止包含堆栈、SQL、底层异常原文、应用内部路径、内部主机配置和敏感信息。授权可见的目标主机、路径、命令及日志属于业务证据时，按最小必要范围提供，禁止与应用调试信息混为一谈。
- 前端请求失败仍统一显示“系统异常”；禁止改写后端详情、按状态码推断原因或增加建议操作。本地校验和已定义业务状态遵循前端规范，不能把请求失败伪装成正常业务状态。
- 新增字段也必须检查消费方解析行为；删改字段前必须搜索路由、模型、前端类型、流式消费、导出及其他已知消费者。破坏性变更必须明确迁移顺序、版本/替代策略及移除条件，并取得相应授权。

接口验证必须核对实际输入输出，而非只看类型声明：正常和非法输入、状态码、字段过滤、失败响应、分页边界及适用的兼容场景。OpenAPI 语法检查、生成客户端或契约检查工具尚未配置时，明确报告缺口；禁止声称已有 CI 自动执行。

## 四、SSE、下载与外部调用

现有 AI 消息流使用 `text/event-stream` 和 `token`、`done`、`error` 事件；前端请求封装负责分帧、解析和校验。修改时必须同步检查后端事件生成、前端解析、正常结束、失败、取消和连接中断语义；禁止把流提前结束当作成功。

现有巡检 Markdown 报告通过 JSON 内容返回，报告归档通过 ZIP 下载。修改时必须分别核对 Schema/文件内容、媒体类型、文件名、动态文本转义、路径边界和失败行为，禁止假设所有导出都使用同一种响应格式。

外部 HTTP、SSH、模型和其他网络调用必须定义连接、读取或整体执行时限、输出/资源上限和取消清理方式，复用现有配置或具名常量。重试必须说明条件、次数或总时限及幂等保障；新增重试、降级、默认数据或备用源仍按既有规则先确认。

## 五、安全检查范围

每次修改必须根据实际入口与数据流检查适用风险，而非为所有任务新增安全框架：

| 入口或数据 | 核查与验证 |
| --- | --- |
| 查询、命令和动态输入 | 服务端类型、长度、范围、格式与业务关系校验；参数化查询、命令边界及异常输入验证 |
| HTML、Markdown 和动态展示 | 按输出上下文转义，检查 XSS；禁止将不可信内容直接作为可执行 HTML |
| 文件、压缩包与解析 | 限制类型、实际内容、大小、存储位置、解压后大小和处理时间，验证路径穿越及资源耗尽边界 |
| URL、回调和代理 | 明确允许协议、地址、重定向和网段；评估 SSRF，同时保持已批准的模型/运维目标访问需求 |
| 敏感操作 | 明确当前访问边界；存在身份体系时，由服务端检查对象、字段和功能权限，并验证允许与拒绝路径 |
| 会话、网络和部署配置 | 在对应功能存在时检查认证、会话、CSRF、CORS、CSP、HTTPS、暴力尝试及速率限制 |
| 依赖与产物 | 检查来源、许可证、版本和漏洞风险；已配置扫描的检查失败禁止被静默忽略 |

前端隐藏按钮或字段不能代替服务端权限控制。新增访问控制采用默认拒绝和完整检查原则，敏感变更必须有可验证的允许与拒绝条件。

当身份体系、管理员操作、角色变更或敏感数据访问功能获准引入时，必须同步定义相应审计，记录操作者、操作、目标对象、时间和结果，明确保留范围、期限及访问控制，并验证记录完整性和脱敏。禁止记录凭据；该条件不表示当前已具备认证或审计系统，也不授权单独新增审计持久化。

## 六、密钥、日志与证据

- 禁止在源码、前端环境变量/产物、测试样例、文档、截图、日志和提交记录中写入真实秘密、凭据或不必要的个人数据。
- 密钥通过项目已有受控配置及加密存储管理；禁止因通用模板要求环境变量而重写现有资产凭据存储。修改加密、密钥和网络边界须先取得相应授权。
- 服务端日志只记录排障所需的类别、目标、状态及已有可用关联信息，并脱敏。禁止未经处理记录完整输入、模型凭据、密码、Token 或私钥；新增关联标识必须有用途，不能无消费者地扩展响应。
- 测试使用虚构且隔离的数据；使用真实业务数据前必须取得授权、脱敏并明确清理方式。
- 发现疑似泄露时，按 [安全策略](../SECURITY.md) 处理，报告受影响的凭据类别和位置，禁止复制秘密；不能只删除文本而忽略撤销或轮换评估。

## 七、安全验证与责任

涉及认证授权、外部输入、文件、URL、敏感数据或网络边界的变更，必须验证对应正常、拒绝、异常和边界行为。修复可复现安全缺陷时，必须增加针对成因的本地回归验证；无法自动化时，记录人工步骤、结果与未覆盖区域。

开发者负责按数据流自查并提供证据；人工审核者复核权限和敏感信息边界。扫描结果、模型自评及参考 OWASP 不代表完成安全认证。未配置的扫描、缺失的访问控制或未核实的部署条件必须如实记录，不能被规范文本本身视为已落实。

已配置 CI 后，维护者必须将选定的依赖漏洞、许可证、秘密和适用的契约检查接入门禁，明确工具、阈值、例外责任与复审条件；本次规范合并不安装工具或创建流水线。
