# AI 接口与安全规范

## 一、适用边界与契约来源

适用于 HTTP、共享接口、流式、下载、外部输入、认证授权、秘密与安全配置。项目技术栈、契约来源、身份和部署边界必须由 [项目配置](../项目配置.md) 核实；认证、多租户和进程模型均须按实际实现确认，不能预设存在或缺失。

接口定义、实现、前端类型和验证必须一致。使用 OpenAPI 时采用已批准且工具支持的版本，禁止模板强制版本或新生成器；SSE、取消与下载等不能完整表达的行为补充契约并核对生产方与消费方。

## 二、接口定义与兼容

每项新增或修改明确用途、唯一操作标识、方法/路径/版本、请求位置与字段、类型/必填/可空/缺省/范围/格式/默认语义、成功与错误状态和结构、权限、分页/排序/筛选/上限、适用幂等及并发、消费者和兼容策略。不适用项说明原因，禁止用猜测或 `any` 补字段。

日期、时区、金额、单位、精度、枚举和状态转换在契约中明确。空列表、缺失资源、字段为空和缺省分别定义；分页说明真实总数、上限和稳定排序。

同类接口沿用既有响应及异常形态，禁止无需求新增统一包装、错误码、关联字段或版本。HTTP 状态真实表达结果，禁止所有错误返回 HTTP 200、伪造成功或用提示文案解析业务状态。

新增字段也检查解析兼容；删改字段搜索全部已知客户端、类型、流式和导出逻辑。破坏性变更说明消费者、迁移顺序、替代/弃用与移除条件，按授权执行并同步模型、消费和文档。

## 三、最小必要输出与失败

模型或白名单限制所有实际输出，禁止直接返回完整实体、内部配置、第三方原始对象或无用途数据。错误、直接响应、流式和文件内容同样检查对象/字段权限、敏感信息和消费用途，前端隐藏不代替过滤。

列表返回必要摘要和分页；低频大明细与原始证据按详情/下载契约提供。授权可见且诊断需要的目标路径、主机和日志是业务证据，不能混为应用内部调试信息或任意删除。

对外错误禁止堆栈、SQL、底层原始异常、内部路径和秘密。服务端安全记录必要上下文；前端按已批准统一政策显示请求错误，本地校验与业务状态分别处理，不因本包擅自改变文案或增加建议操作。

## 四、流、下载与外部服务

SSE 或其他流明确事件类型、字段、编码/分帧、正常结束、失败、心跳、取消和中断语义，修改任一端必须核对另一端。禁止把 EOF、未知或部分完成当成功。

下载明确媒体类型、文件名、内容、转义、编码、路径和失败边界；禁止假定 JSON 报告、文件流和归档具有同一响应契约。外部服务、命令执行或其他 I/O 定义适用超时、资源/输出上限及取消清理；新增重试、备用源或降级先说明并按授权确认。

## 五、安全检查与访问控制

按实际输入与数据流评估注入、XSS、CSRF、SSRF、路径穿越、上传/解析、身份/会话、越权、暴力尝试、滥用、限流、CORS/CSP/HTTPS、秘密及供应链风险。只验证适用入口，禁止为所有任务新增框架或固定安全产品。

- 服务端验证不可信参数、正文、文件、消息和第三方数据的类型、格式、长度、范围与业务关系；查询参数化，动态命令/路径有明确边界。
- HTML/Markdown 按输出上下文处理，禁止插入未经处理的可执行内容；上传检查实际内容、允许类型、大小、位置与文件名，解析/解压限制时间、数量、总大小与路径逃逸。
- URL/回调/代理限制协议、目标、重定向和网段，防止 SSRF，同时核查已批准业务的真实访问需要，禁止以假定规则破坏运维功能。
- 在存在身份体系时，服务端对敏感读取/写入执行对象、字段与功能权限，默认拒绝未明确授权操作，验证允许与拒绝路径；隐藏界面不能保护资源。没有身份体系时如实记录限制，扩展访问范围先设计并授权。
- 当身份、管理员操作、角色变更或敏感访问功能获准接入时，同步定义审计，记录操作者、操作、对象、时间、结果，明确保留期及访问控制并验证脱敏；禁止把凭据写入审计。此条件不授权单独新增审计系统。

## 六、秘密、日志与环境

禁止真实 API Key、密码、Token、Cookie、私钥、生产数据及不必要个人信息进入源码、前端产物、测试、文档、截图、日志、镜像或提交。采用目标已有受控注入/安全存储，不为模板改写密钥机制；疑似泄露按 [安全策略](../SECURITY.md) 评估撤销与轮换，不能只删文本。

日志只保留排障所需类别、目标、状态和已有可用关联信息，并脱敏；禁止未经处理记录完整输入。关联标识不构成无消费者扩展响应的理由。测试使用虚构隔离数据；真实数据需授权、脱敏及清理。

开发、测试和生产隔离敏感配置，禁止将调试、默认账号、宽松访问策略或测试密钥带入生产。网络、认证、加密、密钥、生产写入与高权限依赖变更按已有授权判断，说明影响和恢复方式。

向 AI 服务、搜索工具、MCP 或子代理提供上下文前，核对获准共享的数据范围，仅传递当前任务需要的脱敏内容。禁止将秘密、未获准外传的代码、个人信息或内部日志放入提示词、工具参数、搜索词或链接查询参数；`.gitignore` 不能代替客户端上下文排除和工具访问控制。AI 开发环境的指令信任、工具权限及注入处理按 [编程接入指南](AI-编程接入指南.md) 执行。

## 七、验证与门禁

变更涉及权限、外部输入、文件、URL、秘密或网络边界时，验证对应正常、拒绝、异常、超限和回归行为。接口核对真实请求/输出、字段过滤、错误、流/下载与消费者，不能只看类型声明。

已配置 CI 时，维护者必须将项目选定的依赖漏洞、许可证、秘密及适用的契约检查接入门禁，明确工具、阈值、失败策略、例外责任与复审期限。未配置必须列为缺口，不能声称检查通过，也不能因本包自动安装工具或创建流水线。

实施者提供数据流与验证证据，人工审核者复核安全边界；扫描、模型自评和引用 OWASP 不代表安全认证。未覆盖与未验证项如实交付，禁止静默忽略安全失败。
