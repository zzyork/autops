# AI 项目初始化清单

## 一、接入范围

先按 [接入流程](AI-接入流程.md) 选择文件，检查已有工作约定、目录指令、文档和 Git 状态。已有项目逐项对照、补充与合并；新项目填写真实需求和已批准选择，禁止把模板当既有能力。无需补齐与当前任务无关的全部工程设施后才开始独立工作。

## 二、目标与架构

- [ ] 核实目标、用户、当前范围及可观察验收，明确排除项。
- [ ] 从清单、锁文件和入口核实实际技术栈、运行时、包管理器与版本策略。
- [ ] 核实数据库、迁移、模块边界、依赖方向和公共接口，不为模板重排目录。
- [ ] 记录身份、角色、数据可见性、进程/实例、任务协调及访问边界，不假定已有能力。
- [ ] 在 [项目配置](../项目配置.md) 标注证据、批准与待确认项，将真实代码入口合并到项目索引。

## 三、专项与项目政策

- [ ] 根据实际技术栈及已有授权明确启用、禁用或不适用的专项，文件存在不等于采用。
- [ ] 设备/视口、颜色、品牌、组件库、状态、分页及展开详情与目标设计系统一致。
- [ ] 分别确认本地校验、业务状态、请求错误类型与展示；固定“系统异常”等只在明确采用时执行。
- [ ] 核对测试仅本地政策与目标仓库是否兼容，有冲突先作明确决定，禁止导入自动删测试或取消跟踪。
- [ ] 确认计划、已有授权、待确认的高风险事项、临时方案清理和交付定义。

## 四、契约、安全与运行

- [ ] API、模型、客户端类型、实际响应、流式/下载和错误契约来源一致。
- [ ] 核实外部输入、文件、URL、权限及秘密存储，保留必要过滤、超时、上限与取消清理。
- [ ] 安全报告渠道、负责人及响应时限明确登记，未建立时如实标注。
- [ ] 发布相关任务明确环境隔离、访问授权、产物、迁移顺序、健康和适用监控。
- [ ] 恢复相关任务明确完整备份范围、加密和最小权限访问记录、频率/保留与隔离恢复证据。

## 五、验证与试运行

- [ ] 从配置填写实际检查命令，区分已配置、未配置、不适用与已执行结果。
- [ ] 核实本地测试路径、依赖和受控来源；禁止空收集或工具缺失当成功。
- [ ] 采用测试仅本地政策时，记录理由、受控版本与干净环境复现方式；不能复现的范围如实列出。
- [ ] CI、分支保护、依赖漏洞/许可证/秘密/契约检查如实记录，不假定本包已配置。
- [ ] 需要新增工具时先明确用途、许可、兼容、成本与授权；禁止导入自动安装。
- [ ] 若接入技能，核实实际存在、来源许可、适用差异和客户端加载；没有技能不阻塞直接读规范。
- [ ] 核对客户端版本、启动目录、全局/仓库/子目录规则及覆盖、内容限制，验证正文实际加载；复制链接不等于加载。
- [ ] 核对 AI 上下文共享范围、敏感数据排除、代理及 MCP 的目录/网络/凭据权限；外部内容与子代理输出不能增加授权。
- [ ] 检查目标名称、标识、示例组件、业务条件、域名、绝对路径、部署假设与历史验证记录；只替换确属残留的内容，保留必要出处和批准的专项示例。
- [ ] 选择一个低风险任务试运行“理解—计划—实施—验证—审核—交付”，检查工作区保护、复用、正常/异常和实际报告。

## 六、接入结果

由接入者记录本次合并内容、核实证据、冲突决定、未配置/未验证项及覆盖限制。不适用项有理由，不能以文档复制完成宣称全部上线条件已具备。后续开发按当前任务补齐必要条件，已授权的独立工作持续执行。
