## 三、项目选择与来源边界

- 前端继续使用现有规范的完整约束，包括 TypeScript 禁止 `any`、统一请求层、相同业务规则复用、前端文件行数政策、独立管理页面/路由、桌面大窗口、既有主题和组件、列表分页、统一请求错误、测试状态和展开详情。上游通用规则的较宽适用范围不用于放宽这些要求。
- UI 模板不替代现有设计：现有分页额外提供 100 条选项，不与规范要求至少提供的选项冲突；不因模板导入修改组件行为。未固定的验收高度、缩放、动效或新组件参数仍需按实际需求确认。
- 后端沿用 FastAPI、Pydantic、SQLAlchemy、SQLite、自定义迁移和现有进程内执行器；记录当前未见用户认证/角色体系及未验证多实例协调的边界，不自行增加身份系统、任务平台或生产配置。
- 测试仅本地政策与上游一致，未取消任何跟踪。现有测试的受控来源、版本和干净环境复现方式未登记，持续回归能力不能视为具备。现有 `.agents` 文件已受 Git 跟踪，忽略模式不改变其跟踪状态。
- 根工作约定与已有 OpenCode 配置、命令和只读 Agent 保持现有行为。导入的接入指南连接现有项目技能说明；FastAPI 技能缺少固定上游 SHA，客户端版本、跨环境发现及全局覆盖等仍未全面验证。
- 上游论文、指南和工程实践参考中的“已阅读”“已核对”属于来源包维护记录。本次读取包内文档，没有逐篇联网重读引用，没有重新认证第三方许可、技能来源或安全能力；公开分发许可仍需维护者核实。
